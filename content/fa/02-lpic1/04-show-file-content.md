# نمایش محتوای فایل‌های متنی در لینوکس

## مقدمه

یکی از مفاهیم اساسی و سرشاری در فلسفه طراحی لینوکس این اصل است که **«همه چیز یک فایل است»** (Everything is a file). این مفهوم به معنی آن است که تمام منابع سیستم — از فایل‌های متنی معمول گرفته تا دستگاه‌ها، پورت‌های شبکه‌ای و حتی پردازه‌ها — در لینوکس به‌صورت فایل‌هایی درون سیستم فایل نمایندگی می‌شوند. به همین دلیل، توانایی خواندن و مشاهده‌ی محتوای فایل‌ها یکی از مهارت‌های بنیادی برای هر مدیر سیستم یا کاربر قدرتمند لینوکس است.

در این درس، دستورهای اصلی و ضروری برای نمایش و بررسی محتوای فایل‌های متنی را یاد می‌گیریم. این دستورها نه‌تنها برای خواندن فایل‌های عادی کاربردند، بلکه برای مطالعه فایل‌های پیکربندی سیستم (مثل `/etc/passwd`، `/etc/ssh/sshd_config`)، لاگ‌ها و خروجی‌های برنامه‌ها نیز استفاده می‌شوند و بخش جدایی‌ناپذیری از مسیر یادگیری LPIC-1 هستند.

> **خلاصه مفهوم:** در لینوکس، **همه چیز یک فایل است** و برای کار با آن‌ها باید دستورهای **مختلفی** را بشناسیم. دستورهایی مثل `cat`، `less`، `more`، `head` و `tail` **ابزارهای اصلی** برای **مشاهده و بررسی** محتوای این فایل‌ها هستند، هرکدام برای **موقعیت‌های مختلف** طراحی شده‌اند.

---

## اصل بنیادی: همه چیز فایل است

### فهم مفهوم فایل در لینوکس

در بسیاری از سیستم‌عامل‌های دیگر، مفهوم «فایل» محدود به اسناد و داده‌های ذخیره‌شده است. اما در لینوکس — و به‌طور کلی یونیکس — این مفهوم بسیار گسترده‌تر است:

- **فایل‌های عادی (Regular Files):** اسناد، تصاویر، برنامه‌های اجرایی
- **دایرکتوری‌ها (Directories):** درج‌ها که خود آن‌ها نوعی فایل خاص هستند
- **فایل‌های دستگاه (Device Files):** درایوها، ترمینال‌ها و درگاه‌های مختلف مخزن داده
- **فایل‌های خاص (Special Files):** Pipes، sockets، لینک‌ها و نمادهای سیستمی

این معماری یکپارچه باعث شده که لینوکس بسیار انعطاف‌پذیر و توانمند باشد. برای کار با هر یک از این موارد، ما از **دستورهای مشابه** استفاده می‌کنیم، که برای یادگیری و به‌کارگیری بسیار جالب و کارآمد است.

### چرا نیاز به دستورهای مختلف برای خواندن فایل‌ها؟

شاید این سوال مطرح شود: اگر همه‌جا فایل است، چرا یک دستور واحد نیست؟ پاسخ ساده است: **فایل‌های مختلف اندازه‌های متفاوت** دارند. هنگام باز کردن یک فایل بزرگ (مثلاً یک فایل لاگ کامل با میلیون‌ها خط)، اگر سراسر محتوا را یک‌جا نمایش دهیم، ترمینال سرریز می‌شود و کاربر نمی‌تواند اطلاعات مفید استخراج کند. به همین دلیل، دستورهای مختلفی وجود دارند تا هر کدام به روش‌های متفاوت این مشکل را حل کنند.

## دستورهای نمایش محتوا: نمای کلی

قبل از پرداختن به هر دستور به‌صورت جزئی، بیایید فهرستی از دستورهای اصلی ببینیم:

| دستور | نام انگلیسی | هدف اصلی | موقعیت بهینه |
|:-----:|:-----------:|---------|------------|
| `cat` | concatenate | نمایش کامل فایل | فایل‌های کوچک و متوسط |
| `less` | - | مشاهده صفحه‌ای، جستجو | فایل‌های بزرگ، فایل‌های لاگ |
| `more` | - | مشاهده صفحه‌ای (قدیمی) | سازگاری به‌عقب، سیستم‌های قدیمی |
| `head` | - | نمایش N خط از ابتدا | دیدن آغاز فایل، سرصفحه‌ها |
| `tail` | - | نمایش N خط از انتها | تماشای بروزرسانی‌های فایل لاگ |
| `type` | - | مشخص کردن نوع دستور | فهمیدن اینکه دستور چیست |

## دستور `type`: شناخت نوع دستورها

### مفهوم و کاربرد

دستور `type` یکی از پرکاربردترین دستورات در **Shell** است — که درواقع یک **shell builtin** (دستور داخلی Shell) است. این دستور به شما می‌گوید که یک دستور معین چه نوعی است:

- **Shell Builtin:** دستورهایی که بخش داخلی Shell هستند (مثل `cd`، `pwd`، `type`)
- **External Command:** برنامه‌های اجرایی کامل که در دایرکتوری‌های مشخص نظیر `/usr/bin` یا `/bin` قرار دارند
- **Alias:** نام مستعاری برای دستور دیگری

### نحوه استفاده

```bash
type [command_name]
```

### مثال عملی

```bash
abedini@Mabedini:~$ type pwd
pwd is a shell builtin

abedini@Mabedini:~$ type ip
ip is /usr/bin/ip

abedini@Mabedini:~$ type cat
cat is /usr/bin/cat

abedini@Mabedini:~$ type ls
ls is aliased to 'ls --color=auto'

abedini@Mabedini:~$ type less
less is /usr/bin/less

abedini@Mabedini:~$ type cd
cd is a shell builtin

abedini@Mabedini:~$ type type
type is a shell builtin
```

### تفسیر خروجی

| خروجی | معنا | نکته |
|-----:|-----|-----|
| `shell builtin` | دستور درون Shell است | نیاز به فایل جداگانه ندارد |
| `/path/to/command` | مسیر فایل اجرایی | برنامه‌ای خارجی است |
| `aliased to ...` | نام مستعار برای دستور دیگر | به‌جای دستور اصلی استفاده می‌شود |

## دستور `cat`: نمایش کامل فایل

### مفهوم

دستور `cat` مختصر **concatenate** (ادغام) است. اگرچه نام آن ادغام را پیشنهاد می‌دهد، رایج‌ترین استفاده آن نمایش محتوای یک فایل است. نام `cat` بر اساس کاربردی تاریخی است که در آن این دستور برای **الحاق چندین فایل** به‌کار می‌رفت، اما امروزه بیشتر برای **خواندن یک فایل** استفاده می‌شود.

### نحوه استفاده

```bash
cat [filename]
```

### ویژگی‌های اصلی

- **ساده و سریع:** بدون هیچ تزیین یا ترکیب پیچیده
- **یک‌جا:** کل محتوای فایل را در یک بار نمایش می‌دهد
- **برای فایل‌های کوچک:** اگر فایل خیلی بزرگ باشد، خروجی سریع و غیرقابل کنترل خواهد بود

### مثال عملی

```bash
abedini@Mabedini:~$ cat /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
sync:x:4:65534:sync:/bin:/bin/sync
games:x:5:60:games:/usr/games:/usr/sbin/nologin
man:x:6:12:man:/var/cache/man:/usr/sbin/nologin
lp:x:7:7:lp:/var/spool/lp:/usr/sbin/nologin
mail:x:8:8:mail:/var/mail:/usr/sbin/nologin
news:x:9:9:news:/var/spool/news:/usr/sbin/nologin
uucp:x:10:10:uucp:/var/spool/uucp:/usr/sbin/nologin
proxy:x:13:13:proxy:/bin:/usr/sbin/nologin
abedini:x:1000:1000:abedini:/home/abedini:/bin/bash
ntpsec:x:116:120:ntpsec:/nonexistent:/usr/sbin/nologin
```

> **نکته:** فایل `/etc/passwd` یکی از فایل‌های کلیدی سیستم است که اطلاعات کاربران را ذخیره می‌کند. هر خط نمایندگی یک کاربر است با فیلدهای جداشده‌ی `:` (نام کاربری، رمز عبور هش‌شده، UID، GID و غیره).

## دستور `head`: نمایش خطوط ابتدایی

### مفهوم

دستور `head` نام‌های انتخاب شده اول (سر) یک فایل را نمایش می‌دهد. به‌طور پیش‌فرض، **10 خط اول** را نشان می‌دهد، اما می‌توانیم این عدد را با گزینه‌ی `-n` تغییر دهیم.

### نحوه استفاده

```bash
head [-n number] [filename]
```

### گزینه‌های اصلی

| گزینه | توضیح |
|-----:|-------|
| `-n N` یا `--lines=N` | نمایش N خط اول (default: 10) |
| `-c N` | نمایش N کاراکتر اول |
| `-q` | بدون نمایش نام فایل (در صورت چندین فایل) |

### مثال‌های عملی

```bash
abedini@Mabedini:~$ head /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
sync:x:4:65534:sync:/bin:/bin/sync
games:x:5:60:games:/usr/games:/usr/sbin/nologin
man:x:6:12:man:/var/cache/man:/usr/sbin/nologin
lp:x:7:7:lp:/var/spool/lp:/usr/sbin/nologin
mail:x:8:8:mail:/var/mail:/usr/sbin/nologin
news:x:9:9:news:/var/spool/news:/usr/sbin/nologin

abedini@Mabedini:~$ head -n 2 /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin

abedini@Mabedini:~$ head -n 3 /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
```

> **خطای رایج:** نوشتن `head -n 3-6` فایل بدون فاصله‌ی مناسب. این دستور خطا می‌دهد: `head: invalid number of lines: '3-6'`. دستور `head` تنها از شروع فایل خطوط را نمایش می‌دهد، نه محدوده‌ای دلخواه.

## دستور `tail`: نمایش خطوط انتهایی

### مفهوم

دستور `tail` برعکس `head` کار می‌کند: **آخرین خطوط** یک فایل را نمایش می‌دهد. پیش‌فرض آن نیز **10 خط آخر** است.

### نحوه استفاده

```bash
tail [-n number] [filename]
```

### ویژگی‌های ویژه

- **پیگیری مستمر:** گزینه‌ی `-f` (follow) فایل را به‌طور مستمر پایش می‌کند و خطوط جدید را هنگام اضافه شدن نمایش می‌دهد — بسیار مفید برای نظارت بر لاگ‌های فایل!
- **صرفه‌جویی در حافظه:** برای فایل‌های بزرگ بسیار کارآمد است

### مثال‌های عملی

```bash
abedini@Mabedini:~$ tail /etc/passwd
cups-pk-helper:x:110:113:user for cups-pk-helper service:/nonexistent:/usr/sbin/nologin
fwupd-refresh:x:988:988:Firmware update daemon:/var/lib/fwupd:/usr/sbin/nologin
saned:x:111:116::/var/lib/saned:/usr/sbin/nologin
hplip:x:112:7:HPLIP system user:/run/hplip:/bin/false
lightdm:x:113:117:Light Display Manager:/var/lib/lightdm:/bin/false
polkitd:x:987:987:User for polkit:/usr/sbin/nologin
rtkit:x:114:118:RealtimeKit:/proc:/usr/sbin/nologin
colord:x:115:119:color management daemon:/var/lib/colord:/usr/sbin/nologin
abedini:x:1000:1000:abedini:/home/abedini:/bin/bash
ntpsec:x:116:120:ntpsec:/nonexistent:/usr/sbin/nologin

abedini@Mabedini:~$ tail -n 2 /etc/passwd
abedini:x:1000:1000:abedini:/home/abedini:/bin/bash
ntpsec:x:116:120:ntpsec:/nonexistent:/usr/sbin/nologin
```

### استفاده برای نظارت بر لاگ‌ها

```bash
# نمایش ۲۰ خط آخر فایل لاگ
tail -n 20 /var/log/syslog

# پیگیری مستمر فایل لاگ (Ctrl+C برای خروج)
tail -f /var/log/syslog
```

## دستور `less`: مشاهده‌ی متقدم

### مفهوم و اهمیت

دستور `less` یک **صفحه‌نمایش (pager)** است که برای مشاهده‌ی فایل‌های بزرگ بسیار مناسب است. نام «less» از جملات‌ی کلاسیک لینوکس «less is more» آمده است — که بیان می‌کند که کاهش ویژگی‌ها برخی‌گاه بهتر است!

### ویژگی‌های اصلی

- **جستجو:** می‌توان با `/` کلمات را جستجو کرد
- **ناوبری:** با فضا (space) صفحه تر شود، یا با فلش‌های کلیدها خط‌به‌خط حرکت کرد
- **خروج:** با `q` (quit) از less خارج می‌شویم
- **کارآمد:** حتی برای فایل‌های میلیاردی خط کار می‌کند

### کلیدهای اساسی

| کلید | عملکرد |
|----:|-------|
| `Space` یا `Page Down` | رفتن یک صفحه جلو |
| `b` یا `Page Up` | بازگشت یک صفحه به‌عقب |
| `q` | خروج از less |
| `/pattern` | جستجو برای pattern (پس‌رو) |
| `?pattern` | جستجو برای pattern (پیش‌رو) |
| `n` | رفتن به نتیجه‌ی جستجوی بعدی |
| `N` | رفتن به نتیجه‌ی جستجوی قبلی |
| `g` | رفتن به شروع فایل |
| `G` | رفتن به انتهای فایل |
| `=` | نمایش اطلاعات موقعیت کنونی |

### مثال عملی

```bash
abedini@Mabedini:~$ less /etc/ssh/sshd_config
```

هنگام باز شدن less، می‌توانید:

1. **جستجو برای "PasswordAuthentication":**
   - تایپ کنید: `/PasswordAuthentication` و Enter فشار دهید
   - less تمام تطابق‌ها را برجسته می‌کند

2. **به انتهای فایل رفتن:** `G` فشار دهید

3. **به شروع برگشتن:** `g` فشار دهید

4. **خروج:** `q` فشار دهید

## دستور `more`: صفحه‌نمایش قدیمی

### مفهوم و تاریخچه

دستور `more` **نسخه‌ی قدیمی‌تر** از `less` است و کاربرد کمتری دارد. نام آن از عبارت «press space to see more» آمده است. اگرچه `less` جایگزین بهتر است، اما `more` هنوز در بسیاری از سیستم‌های قدیمی استفاده می‌شود.

### کلیدهای اساسی

| کلید | عملکرد |
|----:|-------|
| `Space` | رفتن یک صفحه جلو |
| `Enter` | رفتن یک خط جلو |
| `q` | خروج |
| `/pattern` | جستجو (محدود) |

### مثال

```bash
abedini@Mabedini:~$ more /etc/ssh/sshd_config
```

> **نکته:** در بسیاری از سیستم‌های مدرن، `more` یک پیوند نمادین (symlink) به `less` است تا سازگاری به‌عقب حفظ شود.

## مقایسه‌ی دستورهای نمایش

جدول زیر مقایسه‌ای جامع از دستورهای نمایش محتوا را ارائه می‌دهد:

| ویژگی | `cat` | `head` | `tail` | `less` | `more` |
|----:|:-:|:-:|:-:|:-:|:-:|
| **سرعت** | ⚡⚡⚡ | ⚡⚡⚡ | ⚡⚡⚡ | ⚡⚡ | ⚡⚡ |
| **جستجو** | ❌ | ❌ | ❌ | ✅ | ✅ (محدود) |
| **حافظه** | معیار | کم | کم | کم | کم |
| **سهولت** | بسیار آسان | آسان | آسان | متوسط | متوسط |
| **مناسب فایل‌های بزرگ** | ❌ | ✅ | ✅ | ✅ | ✅ |
| **پیگیری مستمر (tail -f)** | ❌ | ❌ | ✅ | ❌ | ❌ |

## مثال عملی جامع

بیایید یک فرناریوی واقعی را شبیه‌سازی کنیم: یک مدیر سیستم باید لاگ‌های سرویس SSH را بررسی کند:

```bash
# ۱. ابتدا، مشخص کنیم که ما با چه چیزی سر و کار داریم
user@host:~$ type tail
tail is /usr/bin/tail

# ۲. بررسی آخرین ۵ خط لاگ SSH
user@host:~$ tail -n 5 /var/log/auth.log
Feb 15 10:45:23 server sshd[1234]: Failed password for user1 from 192.168.1.100
Feb 15 10:45:25 server sshd[1235]: Failed password for user1 from 192.168.1.100
Feb 15 10:46:10 server sshd[1240]: Accepted publickey for admin from 192.168.1.50
Feb 15 10:46:11 server sshd[1241]: pam_unix(sshd:session): session opened for user admin
Feb 15 10:47:02 server sshd[1245]: Received disconnect from 192.168.1.100 port 58234

# ۳. برای دیدن بیشتر، یا از head-tail ترکیب استفاده می‌کنیم
user@host:~$ head -n 20 /var/log/auth.log | tail -n 10
# این ۱۰ خط میانی را نمایش می‌دهد

# ۴. یا برای فایل بزرگ، از less استفاده می‌کنیم
user@host:~$ less /var/log/auth.log
# و می‌توانیم با / جستجو کنیم مثلاً: /Failed
```

## نکات اصلاحی و دقیق‌تر

### نکته‌ی اصلاحی ۱: تفاوت `head` و `tail` در دستورات ترکیبی

**باور غلط:** «من می‌توانم از `head -n 3-6` استفاده کنم تا خطوط ۳ تا ۶ را ببینم.»

**اصلاح:** دستور `head` تنها از ابتدا دستیابی می‌کند و از آن‌جا یک محدوده‌ی دلخواه را کاهش نمی‌دهد. برای گرفتن یک محدوده‌ی میانی، باید ترکیبی از `head` و `tail` استفاده کنیم:

```bash
# خطوط ۳ تا ۶ را ببینید
head -n 6 /etc/passwd | tail -n +3
# یا
head -n 6 /etc/passwd | tail -n 4
```

### نکته‌ی اصلاحی ۲: عملکرد `-f` در `tail`

**باور غلط:** «`tail -f` فایل را همیشه باز نگه‌داشته و هیچ‌وقت نمی‌بندد.»

**اصلاح:** `tail -f` واقعاً فایل را **پیگیری می‌کند** و **هنگام تغییر آن** به‌طور خودکار محتوای جدید را نمایش می‌دهد — اما **خیر اگر فایل حذف شود** یا دوباره ساخته شود. برای این موارد از گزینه‌ی `--follow=name` استفاده کنید:

```bash
# پیگیری فایل حتی اگر حذف و دوباره ساخته شود
tail -f --follow=name /var/log/syslog
```

### نکته‌ی اصلاحی ۳: `less` در برابر `more`

**باور غلط:** «`more` و `less` کاملاً یکسان هستند.»

**اصلاح:** `less` **بسیار قدرتمندتر** است. می‌توانید:

- به‌عقب برگردید (در `more` نمی‌توانید)
- جستجو جلو و عقب کنید (در `more` فقط جلو)
- بنابر نیاز بندانید (در `more` حدود `q` محدود است)

`more` تنها برای سازگاری به‌عقب باقی‌مانده است.

### نکته‌ی اصلاحی ۴: صرفه‌جویی حافظه و `cat` برای فایل‌های بزرگ

**باور غلط:** «من می‌توانم `cat` را برای هر فایلی استفاده کنم.»

**اصلاح:** `cat` **کل فایل را به حافظه می‌ریزد.** برای یک فایل لاگ ۱۰ گیگابایتی، این باعث مسائل خطیری می‌شود. همیشه برای فایل‌های بزرگ از `less`، `head` یا `tail` استفاده کنید.

### نکته‌ی اصلاحی ۵: نقش `type` در تشخیص دستورات

**باور غلط:** «`type` تنها برای اطلاعات زیاد است.»

**اصلاح:** `type` **بسیار مفید است** برای فهمیدن که یک دستور **محلی است** (shell builtin) یا **خارجی** (برنامه‌ای). این باعث می‌شود هنگام debug برنامه‌ها از اشتباهات رفتاری اجتناب کنیم — مثلاً `type` نشان می‌دهد که `cd` shell builtin است، نه برنامه‌ای جداگانه.

## جمع‌بندی

دستورهای نمایش محتوا یکی از **بنیادی‌ترین مهارت‌های** کار کردن در لینوکس هستند. درک این‌که کدام دستور برای کدام موقعیت مناسب است، شما را به یک کاربر یا مدیر دقیق و کارآمد تبدیل می‌کند:

- **`cat`** برای فایل‌های کوچک و ساده
- **`head` و `tail`** برای دیدن اجزای خاصی یا پیگیری لاگ‌ها
- **`less` و `more`** برای مشاهده‌ی فایل‌های بزرگ و جستجو

مفهوم اساسی که این درس را پایه‌ی گذاری می‌کند — **«همه چیز یک فایل است»** — اساس تمام فعالیت‌های سیستم‌عامل لینوکس است و بسیاری از درس‌های بعدی (مثل کار با دستگاه‌ها، pipes و redirection) روی این اصل بنا شده‌اند.

درس بعدی، **«ایجاد یک فایل»** را خواهید آموخت که نقطه‌ی طبیعی بعدی برای تسلط بر مدیریت فایل‌ها در لینوکس است. تا آن‌جا، این دستورها را در موقعیت‌های عملی تمرین کنید!
