# ابزارهای شبیه‌سازی شبکه و شروع کار با Packet Tracer

یادگیری شبکه بدون تمرین عملی ناقص می‌ماند، اما تهیهٔ روتر و سوییچ فیزیکی برای هر آزمایش، هم پرهزینه است و هم عملاً غیرممکن. به همین دلیل، جامعهٔ شبکه از ابزارهای مجازی برای طراحی، اتصال و پیکربندی توپولوژی‌ها استفاده می‌کند. پیش از انتخاب ابزار مناسب، باید یک تمایز کلیدی را درک کرد: **Simulation** در برابر **Emulation**. در حالت Simulation (مانند Packet Tracer)، رفتار دستگاه‌ها به‌صورت منطقی و نمایشی بازسازی می‌شود، بدون آنکه سیستم‌عامل واقعی دستگاه اجرا شود؛ در حالت Emulation (مانند GNS3 و EVE-NG)، ایمیج واقعی سیستم‌عامل شبکه (IOS، JunOS و مانند آن) اجرا می‌شود و رفتار دستگاه دقیقاً منطبق با سخت‌افزار واقعی است.

---

## ۱. Cisco Packet Tracer

**تعریف:** Packet Tracer ابزار رسمی شبیه‌سازی شبکهٔ متعلق به سیسکو است که برای آموزش و تمرین پیکربندی دستگاه‌های شبکه طراحی شده. این ابزار امکان طراحی، اتصال و پیکربندی شبکه‌ها را در یک محیط مجازی، بدون نیاز به سخت‌افزار فیزیکی، فراهم می‌کند.

| نقاط قوت | نقاط ضعف |
|---|---|
| رایگان و شروع کار با آن آسان است | فقط Simulation است، Emulation واقعی ندارد |
| رابط گرافیکی ساده و کاربرپسند | از اجرای IOS یا سیستم‌عامل شبکهٔ واقعی پشتیبانی نمی‌کند |
| برای یادگیری پایهٔ شبکه (به‌ویژه CCNA) ایده‌آل است | امکانات پیشرفته محدودتر از GNS3/EVE-NG است |
| نیاز کمی به منابع سخت‌افزاری دارد | گاهی رفتار شبیه‌سازی با سخت‌افزار واقعی متفاوت است |
| از طراحی سناریو و نمایش بصری بسته/خطا پشتیبانی می‌کند | — |
| شامل فعالیت‌های آموزشی و آزمون است | — |

## ۲. GNS3

**تعریف:** GNS3 (Graphical Network Simulator 3) ابزاری حرفه‌ای برای Emulation شبکه است که امکان اجرای سیستم‌عامل‌های شبکهٔ واقعی مانند Cisco IOS، Juniper OS و موارد مشابه را فراهم می‌کند. این ابزار برای طراحی، آزمایش و شبیه‌سازی سناریوهای پیچیدهٔ شبکه در محیطی واقع‌گرایانه ایده‌آل است.

| نقاط قوت | نقاط ضعف |
|---|---|
| اجرای سیستم‌عامل‌های واقعی (IOS، JunOS و ...) را پشتیبانی می‌کند | به منابع سخت‌افزاری قوی نیاز دارد (CPU، RAM) |
| برای سناریوهای پیچیده و واقعی ایده‌آل است | نصب و راه‌اندازی اولیه می‌تواند پیچیده باشد |
| مناسب برای آموزش پیشرفته و آزمایشگاه‌های امنیتی | عملکرد کندتری نسبت به ابزارهای شبیه‌ساز مانند Packet Tracer دارد |
| از یکپارچگی با ماشین‌های مجازی و دستگاه‌های واقعی پشتیبانی می‌کند | — |
| پشتیبانی قوی از جامعهٔ کاربری و مستندات گسترده | — |

## ۳. EVE-NG

**تعریف:** EVE-NG (Emulated Virtual Environment – Next Generation) یکی از پیشرفته‌ترین پلتفرم‌های Emulation شبکه است که امکان اجرای هم‌زمان و متمرکز چند سیستم‌عامل شبکه (Cisco IOS، JunOS، Linux، Windows و غیره) را در یک محیط گرافیکی تحت وب فراهم می‌کند. این ابزار برای آموزش پیشرفته، آزمایش امنیتی و شبیه‌سازی سناریوهای پیچیدهٔ شبکه ایده‌آل است.

| نقاط قوت | نقاط ضعف |
|---|---|
| امکان شبیه‌سازی هم‌زمان چند محیط سیستم‌عامل | به منابع سخت‌افزاری بسیار قوی نیاز دارد (CPU، RAM، فضای ذخیره‌سازی) |
| مدیریت متمرکز و رابط کاربری تحت وب | نصب و راه‌اندازی پیچیده و زمان‌بر است |
| برای سناریوهای پیچیده، امنیتی و چندکاربره ایده‌آل است | نسبت به GNS3 منابع بیشتری مصرف می‌کند |
| امکان همکاری هم‌زمان چند کاربر روی یک سناریوی واحد | نیازمند دانش پیشرفته برای پیکربندی و مدیریت است |
| از قابلیت‌های Automation و یکپارچگی با API پشتیبانی می‌کند | — |

> **جمع‌بندی انتخاب ابزار:** برای شروع یادگیری و آماده‌شدن برای آزمون‌هایی مانند CCNA، Packet Tracer به‌دلیل سادگی و سبک بودن گزینهٔ مناسبی است. برای سناریوهای واقعی‌تر و آماده‌سازی برای محیط کاری واقعی یا آزمایشگاه‌های امنیتی پیشرفته، GNS3 و به‌ویژه EVE-NG (با پشتیبانی هم‌زمان از چند سیستم‌عامل و مدیریت تحت وب) گزینه‌های حرفه‌ای‌تری هستند.

## ۴. نصب Cisco Packet Tracer روی ویندوز

پیش از اجرای نصب، توصیه می‌شود Windows Security و بخش Virus & Threat Protection بررسی شود تا در میانهٔ نصب با مسدودسازی غیرمنتظره مواجه نشوید.

1. فایل نصب دانلودشده (`CiscoPacketTracer_8.2.x64_setup.exe` یا نسخهٔ مشابه) را از پوشهٔ Downloads اجرا کنید.
2. در صورت نمایش هشدار **SmartScreen**، پس از اطمینان از صحت منبع فایل، گزینهٔ ادامهٔ اجرا را انتخاب کنید.
3. در پنجرهٔ **User Account Control**، از صحت ناشر (Publisher: **CISCO SYSTEMS, INC.**) اطمینان حاصل کرده و روی **Yes** کلیک کنید.
4. مراحل ویزارد نصب (Setup Wizard) را تا رسیدن به پیام **Completing the Cisco Packet Tracer Setup Wizard** دنبال کنید.
5. پس از پایان نصب، برنامه را اجرا کنید؛ صفحهٔ آغازین با پیام **"Try Simulation Mode to see how packets travel through your network"** نمایش داده می‌شود.

> **نکتهٔ عملی:** اگر پس از نصب، اتصال دستگاه‌های داخل Packet Tracer به‌درستی برقرار نمی‌شود یا برنامه در دریافت به‌روزرسانی مشکل دارد، تنظیمات Windows Defender Firewall (به‌ویژه Private و Public Profile) را بررسی کنید؛ گاهی سیاست‌های پیش‌فرض فایروال ارتباط داخلی برنامه را محدود می‌کنند.

## ۵. شروع کار با محیط Packet Tracer

### ساختار کلی محیط

فضای کاری Packet Tracer از دو حالت نمایش تشکیل شده: **Logical** (نمایش منطقی و شماتیک توپولوژی) و **Physical** (نمایش فیزیکی دستگاه‌ها، مانند قرارگیری در قفسه یا داخل یک ساختمان). در پایین صفحه، نوار دسته‌بندی دستگاه‌ها قرار دارد که شامل دسته‌های اصلی زیر است:

| دسته | نمونه دستگاه‌ها |
|---|---|
| Routers | انواع روترهای سیسکو |
| Switches | سوییچ‌های Layer 2 و Layer 3 (مانند 2960-24TT) |
| Hubs | هاب‌های ساده |
| Wireless Devices | Access Point، روترهای بی‌سیم |
| Connections | انواع کابل (Copper Straight-through، Crossover، Console، Fiber) |
| End Devices | PC، Laptop، Server، Printer، تلفن IP |
| WAN Emulation | شبیه‌سازی لینک‌های WAN |
| Custom Made Devices | تلویزیون، PDA، Traffic Generator و دستگاه‌های سفارشی دیگر |

### افزودن و اتصال دستگاه‌ها

1. از نوار پایین، دستگاه موردنظر (برای مثال یک Switch از دستهٔ Switches، یا یک PC از دستهٔ End Devices) را با درگ‌ودراپ روی فضای کاری قرار دهید.
2. برای اتصال دو دستگاه، از دستهٔ **Connections** نوع کابل مناسب را انتخاب کرده (برای اتصال PC به Switch معمولاً Copper Straight-through) و روی هر دو دستگاه کلیک کنید تا کابل بین پورت‌های آن‌ها برقرار شود.
3. با کلیک روی هر دستگاه، پنجرهٔ تنظیمات آن باز می‌شود که شامل تب‌های **Physical** (نمایش شاسی و امکان افزودن ماژول‌های سخت‌افزاری)، **Config** (تنظیمات گرافیکی ساده)، **CLI** یا **Desktop → Terminal** (دسترسی به خط‌فرمان واقعی IOS) و **Attributes** است.

### دسترسی به کنسول CLI

برای دستگاه‌هایی مانند Switch و Router، می‌توان از طریق کابل Console (یا مستقیماً از تب Config/CLI) به خط‌فرمان IOS دسترسی یافت. نمونه‌ای از خروجی واقعی این کنسول پس از اتصال به یک سوییچ:

```
Switch Ports Model              SW Version            SW Image
----- ----- -----               ----------            ----------
*    1  26  WS-C2960-24TT-L     15.0(2)SE4            C2960-LANBASEK9-M

Cisco IOS Software, C2960 Software (C2960-LANBASEK9-M), Version 15.0(2)SE4, RELEASE SOFTWARE (fc1)
Technical Support: http://www.cisco.com/techsupport
Copyright (c) 1986-2013 by Cisco Systems, Inc.

Press RETURN to get started!

%LINK-5-CHANGED: Interface FastEthernet0/1, changed state to up
%LINEPROTO-5-UPDOWN: Line protocol on Interface FastEthernet0/1, changed state to up

Switch>
```

مشاهدهٔ خط `Switch>` به این معناست که کنسول در حالت **User EXEC Mode** آمادهٔ دریافت دستور است — نقطهٔ آغاز برای هر نوع پیکربندی بعدی مانند تغییر نام دستگاه، تنظیم آدرس IP روی VLAN مدیریتی یا پیکربندی پورت‌ها.

> **نکتهٔ آزمون:** پیام‌های `%LINK-5-CHANGED` و `%LINEPROTO-5-UPDOWN` که به‌محض اتصال کابل ظاهر می‌شوند، به‌ترتیب نشان‌دهندهٔ فعال‌شدن لایهٔ فیزیکی (Layer 1) و بالا آمدن پروتکل خط روی آن اینترفیس (Layer 2) هستند؛ نبود این دو پیام پس از اتصال کابل، نخستین نشانهٔ یک مشکل فیزیکی یا پیکربندی نادرست پورت است.
