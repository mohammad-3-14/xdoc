## مقدمه

هر بستهٔ داده، از لحظهٔ خروج از یک کامپیوتر تا رسیدن به مقصد نهایی، از میان چندین دستگاه شبکه عبور می‌کند. هرکدام از این دستگاه‌ها در یکی از لایه‌های مدل OSI فعالیت می‌کنند و وظیفهٔ مشخصی بر عهده دارند: برخی صرفاً سیگنال را تکرار می‌کنند، برخی بر اساس آدرس MAC تصمیم می‌گیرند، برخی مسیر بین شبکه‌ها را بر اساس آدرس IP انتخاب می‌کنند و برخی دیگر محتوای واقعی ترافیک را برای اهداف امنیتی یا بهینه‌سازی بررسی می‌کنند. شناخت دقیق این دستگاه‌ها و تفاوت‌های ظریف میان آن‌ها یکی از پایه‌ای‌ترین نیازهای هر متخصص شبکه است، چه در محیط کار و چه در آزمون‌های تخصصی مانند CompTIA Network+.

در این مطلب، تجهیزات شبکه به ترتیب لایه‌ای که در آن فعالیت می‌کنند بررسی می‌شوند: از دستگاه‌های لایهٔ فیزیکی و پیوند داده (Hub، Bridge، Switch)، به دستگاه لایهٔ شبکه (Router)، سپس دستگاه‌های بی‌سیم (Wireless Access Point)، دستگاه‌های امنیتی (Firewall، NGFW، IDS/IPS) و در نهایت دستگاه‌های لایهٔ اپلیکیشن و بهینه‌سازی ترافیک (Proxy Server، Load Balancer، Packet Shaper).

## انواع ارسال داده در شبکه: پیش‌نیازی برای درک Hub و Switch

پیش از ورود به بحث دستگاه‌ها، باید سه الگوی اصلی ارسال داده در یک شبکه را از هم تفکیک کرد، زیرا رفتار Hub در برابر Switch دقیقاً بر همین مبنا تفاوت می‌کند:

| نوع ارسال | مقصد | مثال |
|---|---|---|
| Unicast | یک مقصد مشخص و واحد | کامپیوتر A فایلی را مستقیماً برای کامپیوتر B ارسال می‌کند |
| Multicast | گروهی مشخص از مقصدها که عضویت در آن گروه را دارند | پخش زندهٔ ویدیویی برای مجموعه‌ای از کاربران عضو یک گروه چندپخشی |
| Broadcast | تمام میزبان‌های موجود در یک دامنهٔ پخش (Broadcast Domain) | درخواست ARP برای یافتن آدرس MAC متناظر با یک IP |

> نکتهٔ آزمون: عبارت «all-hosts» تقریباً همیشه اشاره به Broadcast دارد، در حالی که «a specific group that subscribed» نشانهٔ Multicast است. تشخیص این دو عبارت در سؤالات چندگزینه‌ای Network+ بسیار پرتکرار است.

## دستگاه‌های لایهٔ فیزیکی و پیوند داده

### Hub

Hub ساده‌ترین دستگاه اتصال‌دهندهٔ چند کامپیوتر در یک LAN است. Hub در لایهٔ فیزیکی (Layer 1) مدل OSI فعالیت می‌کند و به همین دلیل هیچ آگاهی‌ای از آدرس MAC یا IP ندارد؛ صرفاً سیگنال الکتریکی ورودی از یک پورت را روی تمام پورت‌های دیگر تکرار (Repeat) می‌کند.

فرض کنید کامپیوتر A می‌خواهد داده‌ای را فقط برای کامپیوتر B ارسال کند. از دید منطقی این یک ارتباط Unicast است، اما چون Hub قادر به تشخیص مقصد نیست، دادهٔ A را به‌صورت Broadcast برای همهٔ پورت‌ها (از جمله C و D) ارسال می‌کند. تمام کامپیوترهای متصل به Hub، فریم را دریافت می‌کنند و تنها مقصد واقعی (B) آن را پردازش کرده و بقیه آن را نادیده می‌گیرند.

این رفتار دو پیامد مهم دارد:

- تمام پورت‌های یک Hub در یک **Collision Domain** واحد قرار دارند؛ یعنی اگر دو دستگاه هم‌زمان ارسال کنند، سیگنال‌ها با هم برخورد (Collision) کرده و باید مجدداً ارسال شوند. هرچه تعداد دستگاه‌های متصل به Hub بیشتر باشد، احتمال Collision و در نتیجه افت کارایی شبکه بیشتر می‌شود.
- تمام پورت‌های Hub همچنین در یک **Broadcast Domain** واحد نیز قرار دارند.

> نکتهٔ آزمون: قانون کلاسیک «Collision Domain بزرگ‌تر = کارایی کمتر» دقیقاً همین‌جا معنا پیدا می‌کند. Hub بدترین حالت ممکن از نظر اندازهٔ Collision Domain است، زیرا همهٔ پورت‌ها یک Collision Domain مشترک دارند.

از نظر تاریخی، Hub با استاندارد Ethernet نیمه‌دوطرفه (Half-Duplex) و مکانیزم CSMA/CD (تعریف‌شده در IEEE 802.3) کار می‌کرد؛ یعنی هر دستگاه پیش از ارسال باید بررسی می‌کرد که خط آزاد است، و در صورت وقوع Collision، پس از یک تأخیر تصادفی مجدداً تلاش می‌کرد. امروزه به دلیل ازدحام شدید و عدم مقیاس‌پذیری، Hub تقریباً به‌طور کامل با Switch جایگزین شده و صرفاً در آزمایشگاه‌های آموزشی یا برای Packet Sniffing قدیمی دیده می‌شود.

### Bridge

Bridge دستگاهی است که دو یا چند سگمنت شبکه را به هم متصل می‌کند و برخلاف Hub، در لایهٔ پیوند داده (Layer 2) فعالیت می‌کند. Bridge با یادگیری آدرس‌های MAC دستگاه‌های هر سگمنت، تصمیم می‌گیرد که آیا یک فریم باید از یک سگمنت به سگمنت دیگر عبور کند یا خیر.

در یک پیکربندی نمونه، دو Hub جداگانه (هرکدام با دو میزبان) توسط یک Bridge به هم متصل می‌شوند. اگر Host A بخواهد با Host B (که هر دو به Hub 1 متصل هستند) ارتباط برقرار کند، Bridge تشخیص می‌دهد که مقصد در همان سگمنت محلی قرار دارد و ترافیک را به سگمنت دوم (Hub 2) عبور نمی‌دهد. این کار باعث می‌شود هر سگمنت، Collision Domain جداگانهٔ خودش را داشته باشد؛ در نتیجه با اضافه‌شدن یک Bridge، یک Collision Domain بزرگ به دو Collision Domain کوچک‌تر تقسیم می‌شود، هرچند هر دو سگمنت همچنان در یک Broadcast Domain مشترک باقی می‌مانند.

> نکتهٔ عملی: Bridge دقیقاً همان کاری را انجام می‌دهد که یک Switch مدرن انجام می‌دهد، اما با تعداد پورت بسیار محدودتر (معمولاً فقط ۲ تا ۴ پورت) و پردازش نرم‌افزاری کندتر. از این جهت می‌توان Switch را «Bridge چندپورته با پردازش سخت‌افزاری (ASIC)» در نظر گرفت.

### Switch

Switch نیز مانند Bridge در لایهٔ پیوند داده فعالیت می‌کند، اما با ظرفیت پورت بسیار بیشتر و سرعت پردازش به‌مراتب بالاتر (به لطف مدارهای ASIC اختصاصی به‌جای پردازش نرم‌افزاری). Switch جدولی به نام **MAC Address Table** (یا CAM Table) می‌سازد که در آن آدرس MAC هر دستگاه را به شمارهٔ پورت متصل به آن نگاشت می‌کند.

وقتی فریمی وارد Switch می‌شود:

1. اگر آدرس MAC مقصد در جدول موجود باشد، فریم فقط به همان پورت خاص ارسال می‌شود (Unicast هوشمند).
2. اگر آدرس MAC مقصد ناشناخته باشد، Switch فریم را به تمام پورت‌ها به‌جز پورت ورودی می‌فرستد (رفتاری شبیه Flooding که تنها در همین حالت رخ می‌دهد).
3. اگر فریم به یک گروه Multicast خطاب شده باشد، تنها به پورت‌های عضو آن گروه ارسال می‌شود.

نتیجهٔ مستقیم این رفتار آن است که **هر پورت Switch یک Collision Domain جداگانه است**؛ برخلاف Hub که تمام پورت‌ها یک Collision Domain مشترک داشتند. این تفاوت، مهم‌ترین دلیل برتری Switch نسبت به Hub است.

| ویژگی | Hub | Switch |
|---|---|---|
| لایهٔ OSI | Layer 1 (فیزیکی) | Layer 2 (پیوند داده) |
| مبنای تصمیم‌گیری | ندارد؛ فقط تکرار سیگنال | آدرس MAC |
| Collision Domain | یک Collision Domain مشترک برای همهٔ پورت‌ها | یک Collision Domain جداگانه برای هر پورت |
| Broadcast Domain | یک Broadcast Domain مشترک | یک Broadcast Domain مشترک (مگر با VLAN) |
| حالت انتقال | Half-Duplex | معمولاً Full-Duplex |
| هزینه و کاربرد امروزی | تقریباً منسوخ | استاندارد فعلی شبکه‌های LAN |

| ویژگی | Bridge | Switch |
|---|---|---|
| تعداد پورت | معمولاً ۲ تا ۴ پورت | از ۸ تا صدها پورت |
| نوع پردازش | نرم‌افزاری (کندتر) | سخت‌افزاری با ASIC (بسیار سریع‌تر) |
| کاربرد امروزی | تقریباً منسوخ، مفهومی آموزشی | استاندارد فعلی برای اتصال درون‌شبکه‌ای |
| مبنای تصمیم | آدرس MAC | آدرس MAC (و در Switch لایه ۳، آدرس IP نیز) |

سوییچ‌های مدیریت‌شده (Managed Switch) قابلیت‌های پیشرفته‌تری مانند VLAN، QoS و Port Security ارائه می‌دهند:

- **VLAN (Virtual LAN)** به مدیر شبکه اجازه می‌دهد پورت‌های یک Switch فیزیکی را به چند Broadcast Domain منطقی و مجزا تقسیم کند؛ برای مثال می‌توان کامپیوترهای واحد منابع انسانی (HR) و واحد فروش (Sales) را در یک Switch فیزیکی مشترک نگه داشت اما ترافیک Broadcast هرکدام را کاملاً از دیگری ایزوله کرد، درست به‌گونه‌ای که گویی هرکدام Switch فیزیکی جداگانه‌ای دارند. استاندارد **IEEE 802.1Q** نحوهٔ افزودن یک برچسب (Tag) چهار بایتی حاوی شناسهٔ VLAN (VLAN ID، در بازهٔ ۱ تا ۴۰۹۴) به فریم اترنت را مشخص می‌کند.
- **QoS (Quality of Service)** امکان اولویت‌بندی ترافیک حساس به تأخیر (مانند صدا و تصویر) نسبت به ترافیک عادی را فراهم می‌کند؛ این مفهوم در بخش Packet Shaper با جزئیات بیشتری بررسی می‌شود.
- **Port Security** با محدودکردن تعداد یا نوع آدرس‌های MAC مجاز روی هر پورت، از اتصال دستگاه‌های ناشناس یا حملاتی مانند MAC Flooding جلوگیری می‌کند.

سوییچ‌های لایهٔ ۳ (Layer 3 Switch یا Multilayer Switch) قابلیت مسیریابی بین VLANها را نیز اضافه می‌کنند و در واقع ترکیبی از Switch و Router در یک دستگاه هستند:

| ویژگی | Switch لایه ۲ | Switch لایه ۳ (Multilayer) |
|---|---|---|
| مبنای فوروارد | فقط آدرس MAC | آدرس MAC درون یک VLAN و آدرس IP بین VLANها |
| مسیریابی بین VLAN | ندارد؛ نیازمند Router خارجی (Router-on-a-Stick) | دارد، با سرعت سخت‌افزاری (Wire-Speed Routing) |
| کاربرد معمول | اتصال میزبان‌ها درون یک سگمنت | Core و Distribution Layer شبکه‌های سازمانی بزرگ |

> نکتهٔ آزمون: اگر سؤال دربارهٔ دستگاهی باشد که «هم بر اساس MAC و هم بر اساس IP تصمیم می‌گیرد»، پاسخ صحیح معمولاً **Layer 3 Switch** است، نه Router ساده.

## دستگاه لایهٔ شبکه

### Router

Router دستگاهی است که بستهٔ داده را بین شبکه‌های مجزا (نه صرفاً پورت‌های یک شبکهٔ محلی) هدایت می‌کند و در لایهٔ شبکه (Layer 3) بر اساس آدرس IP تصمیم می‌گیرد. برخلاف Switch که یک Broadcast Domain واحد را به اشتراک می‌گذارد، Router مرز هر Broadcast Domain را مشخص می‌کند؛ یعنی ترافیک Broadcast به‌طور پیش‌فرض از یک اینترفیس Router به اینترفیس دیگر عبور نمی‌کند.

Router با استفاده از جدول مسیریابی (Routing Table) و پروتکل‌های مسیریابی (مانند OSPF یا BGP) «بهترین مسیر» (Best Route) را برای رساندن بسته به مقصد انتخاب می‌کند. معیار «بهترین» می‌تواند بر اساس کمترین تعداد Hop، کمترین تأخیر یا پهنای باند در دسترس باشد، بسته به پروتکل مسیریابی مورد استفاده.

نکتهٔ مهم دیگر دربارهٔ Router، وابستگی آن به **ARP (Address Resolution Protocol، تعریف‌شده در RFC 826)** است: پیش از آنکه Router بتواند بسته را در همان سگمنت محلی تحویل دهد، باید آدرس MAC متناظر با آدرس IP مقصد را از طریق یک درخواست Broadcast به نام ARP Request به دست آورد. این فرایند، پل ارتباطی میان لایهٔ ۳ (IP) و لایهٔ ۲ (MAC) است.

Router علاوه بر مسیریابی، معمولاً قابلیت‌های زیر را نیز ارائه می‌دهد:

- **NAT (Network Address Translation)**: بر اساس RFC 3022، ترجمهٔ آدرس‌های IP خصوصی یک شبکهٔ داخلی به یک یا چند آدرس IP عمومی، که رایج‌ترین شکل آن یعنی PAT (Port Address Translation یا NAT Overload) امکان می‌دهد هزاران میزبان داخلی از طریق تفاوت در شمارهٔ پورت، تنها با یک آدرس IP عمومی به اینترنت متصل شوند.
- **DHCP (Dynamic Host Configuration Protocol)**: تخصیص خودکار آدرس IP، Gateway و DNS به میزبان‌های تازه‌متصل‌شده.
- امکانات امنیتی پایه مانند فیلترکردن بستهٔ ساده (Packet Filtering) که در ادامه با Firewall تخصصی مقایسه می‌شود.

| ویژگی | Switch (لایه ۲) | Router (لایه ۳) |
|---|---|---|
| مبنای فوروارد | آدرس MAC | آدرس IP |
| مرزبندی Broadcast Domain | خیر (مگر با VLAN) | بله؛ هر اینترفیس یک Broadcast Domain جداست |
| اتصال شبکه‌های متفاوت | خیر، فقط درون یک شبکه | بله، وظیفهٔ اصلی آن همین است |
| نیاز به ARP | ندارد | دارد، برای تحویل نهایی در سگمنت محلی |
| نمونه کاربرد | اتصال کامپیوترها در یک دفتر | اتصال شبکهٔ دفتر به اینترنت یا شعبهٔ دیگر |

> نکتهٔ عملی: بسیاری از کاربران خانگی، دستگاه «مودم‌روتر» خود را صرفاً «روتر» می‌نامند، در حالی که این دستگاه معمولاً ترکیبی از Modem، Router، Switch چندپورته و Wireless Access Point در یک بدنهٔ واحد است. در آزمون Network+ باید این چهار عملکرد را از هم تفکیک کرد.

## دستگاه‌های بی‌سیم

### Wireless Access Point (WAP)

Wireless Access Point دستگاهی است که دستگاه‌های بی‌سیم را قادر می‌سازد به یک شبکهٔ سیمی متصل شوند. از نظر عملکردی، WAP نقشی مشابه یک Switch ایفا می‌کند اما به‌جای پورت‌های سیمی، مشتریان را بر اساس **SSID** (نام شبکهٔ بی‌سیم که تبلیغ/Broadcast می‌شود) شناسایی کرده و پس از فرایند احراز هویت و اتصال (Association)، به هرکدام آدرس MAC اختصاصی خودشان را نگاشت می‌کند.

WAP می‌تواند دستگاه مستقل باشد یا در دستگاه‌های ترکیبی (مانند مودم‌روتر خانگی) ادغام شود. WAPها از استانداردهای خانوادهٔ **IEEE 802.11** (مانند 802.11ac یا 802.11ax موسوم به Wi-Fi 6) پیروی می‌کنند. دو باند فرکانسی رایج عبارت‌اند از:

- باند ۲.۴ گیگاهرتز: برد بیشتر، نفوذ بهتر از دیوار، اما پهنای باند کمتر و تداخل بیشتر با دستگاه‌هایی مانند مایکروویو و بلوتوث.
- باند ۵ گیگاهرتز: پهنای باند و سرعت بالاتر، اما برد کمتر و حساسیت بیشتر به موانع فیزیکی.

> نکتهٔ آزمون: تفاوت WAP با «Wireless Router» دقیقاً مشابه تفاوت Switch با Router است. WAP به‌تنهایی نه DHCP دارد، نه NAT و نه مسیریابی؛ صرفاً پل ارتباطی لایهٔ ۲ میان دنیای بی‌سیم و شبکهٔ سیمی است. اگر سؤال دربارهٔ دستگاهی باشد که «فقط پوشش بی‌سیم را گسترش می‌دهد بدون تغییر در آدرس‌دهی»، پاسخ WAP است نه Router.

| ویژگی | Router (سیمی/بی‌سیم ترکیبی) | Wireless Access Point |
|---|---|---|
| لایهٔ اصلی عملکرد | Layer 3 | Layer 2 |
| DHCP/NAT | معمولاً دارد | ندارد |
| اتصال به اینترنت | مستقیماً یا از طریق Modem | نیاز به یک Router/Switch بالادستی دارد |
| هدف اصلی | اتصال شبکه‌ها به یکدیگر | گسترش پوشش بی‌سیم یک شبکهٔ موجود |

## دستگاه‌های امنیتی شبکه

### Firewall

Firewall دستگاه امنیتی است که ترافیک ورودی و خروجی را بر اساس مجموعه‌ای از قواعد از پیش تعریف‌شده (Rule Base) بررسی و کنترل می‌کند و به‌عنوان مانعی میان یک شبکهٔ داخلی مورد اعتماد و شبکه‌های خارجی نامعتبر (مانند اینترنت) عمل می‌کند. Firewallهای سنتی (Stateless یا Stateful Packet Filtering) عمدتاً در لایهٔ ۴ (Transport) مدل OSI فعالیت می‌کنند و تصمیم Permit/Deny خود را بر مبنای یک مجموعه پنج‌تایی معروف به **5-Tuple** می‌گیرند:

1. آدرس IP مبدأ (Source IP)
2. آدرس IP مقصد (Destination IP)
3. شمارهٔ پورت مبدأ (Source Port)
4. شمارهٔ پورت مقصد (Destination Port)
5. پروتکل (مانند TCP، UDP یا ICMP)

برای مثال، یک قانون Firewall می‌تواند به‌صراحت ترافیکی را که از یک آدرس IP مشخص و شناخته‌شده به‌عنوان مخرب (Bad IP) وارد می‌شود، مسدود کند، در حالی که ترافیک مجاز از سایر منابع را عبور دهد.

> نکتهٔ عملی: بسیاری از پیاده‌سازی‌های عملی، فقط چهار مورد از این پنج فیلد (بدون Source Port) را در قوانین ساده نشان می‌دهند، زیرا پورت مبدأ در ارتباطات معمولی TCP/IP به‌صورت پویا و تصادفی انتخاب می‌شود و کمتر برای فیلترکردن استفاده می‌شود؛ اما در تعریف رسمی 5-Tuple، این فیلد نیز جزئی جدایی‌ناپذیر است.

### Next-Generation Firewall (NGFW)

NGFW نسخهٔ پیشرفته‌تری از Firewall سنتی است که علاوه بر فیلترکردن بر مبنای 5-Tuple، قابلیت‌های زیر را نیز ارائه می‌دهد:

- **Deep Packet Inspection (DPI)**: بررسی محتوای واقعی (Data/Payload) بسته تا لایهٔ ۷ (Application)، نه فقط سرآیندهای لایهٔ ۳ و ۴.
- **Application Control**: شناسایی و کنترل ترافیک بر اساس برنامهٔ واقعی تولیدکنندهٔ آن (مثلاً تفکیک ترافیک یک برنامهٔ پیام‌رسان خاص از ترافیک عمومی HTTPS، حتی اگر هر دو از پورت ۴۴۳ استفاده کنند).
- **Intrusion Prevention** یکپارچه (که در ادامه با جزئیات بیشتری در بخش IDS/IPS بررسی می‌شود).

| ویژگی | Firewall سنتی | Next-Generation Firewall |
|---|---|---|
| لایهٔ عملکرد اصلی | Layer 4 (Transport) | تا Layer 7 (Application) |
| مبنای تصمیم | 5-Tuple (IP/Port/Protocol) | 5-Tuple + محتوای بسته + شناسایی برنامه |
| تشخیص ترافیک مخرب پنهان در پورت‌های مجاز | خیر | بله، از طریق DPI |
| هزینهٔ پردازشی | کم | بیشتر؛ فعال‌سازی DPI معمولاً توان عبوری (Throughput) دستگاه را به میزان محسوسی (در برخی پیاده‌سازی‌ها تا ۳۰ تا ۵۰ درصد) کاهش می‌دهد |

> نکتهٔ آزمون: کلیدواژه‌های «Layer 7»، «Deep Packet Inspection» و «Application-aware» تقریباً همیشه به NGFW اشاره دارند، در حالی که «5-Tuple» و «Stateful Inspection» به تنهایی معمولاً توصیف‌کنندهٔ Firewall سنتی هستند.

### Intrusion Detection System (IDS) و Intrusion Prevention System (IPS)

IDS و IPS هر دو فناوری‌های امنیتی برای شناسایی الگوهای ترافیک مخرب هستند، اما تفاوت بنیادین آن‌ها در نحوهٔ استقرار و واکنش است:

- **IDS** به‌صورت **Out-of-Band** (معمولاً از طریق یک پورت Mirror/SPAN روی Switch) ترافیک را رصد می‌کند. IDS تنها **هشدار (Alert)** صادر می‌کند و خودش ترافیک را متوقف نمی‌کند؛ بنابراین یک بستهٔ مخرب همچنان به مقصد می‌رسد، اما مدیر شبکه از وقوع آن مطلع می‌شود.
- **IPS** به‌صورت **Inline** در مسیر مستقیم ترافیک قرار می‌گیرد (درست مانند یک Firewall) و در صورت تطبیق ترافیک با یک قاعدهٔ مخرب شناخته‌شده، آن بسته را در لحظه **مسدود (Block)** می‌کند، پیش از آنکه به مقصد برسد.

برای مثال، وقتی ترافیکی از یک منبع خارجی وارد یک Server Farm می‌شود، ابتدا با مجموعه‌ای از قواعد شناسایی مقایسه می‌شود؛ اگر این تطبیق در یک IPS رخ دهد، بستهٔ مخرب همان‌جا متوقف می‌شود و هرگز به سرورها نمی‌رسد، اما اگر همان تشخیص در یک IDS رخ دهد، تنها یک هشدار برای تیم امنیتی ثبت می‌شود در حالی که بسته به مسیر خود ادامه می‌دهد.

| ویژگی | IDS | IPS |
|---|---|---|
| موقعیت در مسیر ترافیک | Out-of-Band (از طریق Tap یا SPAN Port) | Inline (مستقیماً در مسیر ترافیک) |
| واکنش به تهدید | فقط هشدار (Detect & Alert) | مسدودسازی فعال (Block در لحظه) |
| تأثیر بر تأخیر شبکه (Latency) | تقریباً هیچ، زیرا مسیر اصلی را قطع نمی‌کند | افزودن تأخیر جزئی (میکروثانیه تا چند میلی‌ثانیه) به دلیل قرارگیری در مسیر |
| ریسک اصلی | تهدید شناسایی‌شده همچنان به مقصد می‌رسد | False Positive می‌تواند ترافیک قانونی را نیز مسدود کند |

> نکتهٔ آزمون: عبارت کلیدی برای تشخیص این دو در سؤالات چندگزینه‌ای این است: اگر متن سؤال بگوید دستگاه «traffic را block می‌کند»، پاسخ IPS است؛ اگر بگوید فقط «alert می‌دهد» یا «log می‌کند»، پاسخ IDS است.

## دستگاه‌های لایهٔ اپلیکیشن و بهینه‌سازی ترافیک

### Proxy Server

Proxy Server به‌عنوان واسطه‌ای میان یک کلاینت (مثلاً کامپیوتر کاربر) و اینترنت عمل می‌کند. به‌جای آنکه دستگاه کاربر مستقیماً به یک وب‌سایت متصل شود، درخواست را برای Proxy می‌فرستد، Proxy آن درخواست را از طرف کاربر به مقصد (مثلاً google.com) ارسال می‌کند، پاسخ را دریافت کرده و آن را به کاربر بازمی‌گرداند. از دید سرور مقصد، این درخواست از سوی Proxy می‌رسد، نه از سوی کلاینت اصلی.

| کاربرد (Purpose) | توضیح |
|---|---|
| Privacy | آدرس IP واقعی کلاینت را از دید مقصد پنهان می‌کند |
| Access Control | مدیران شبکه می‌توانند دسترسی به وب‌سایت‌های خاص را مسدود یا مجاز کنند |
| Caching | صفحات پرتکرار را ذخیره می‌کند تا سرعت را افزایش و مصرف پهنای باند را کاهش دهد |
| Monitoring | فعالیت کاربران را برای اهداف امنیتی و اجرای سیاست‌های سازمانی ثبت می‌کند |
| Bypass Restrictions | می‌تواند به کاربران کمک کند به محتوای مسدودشده یا محدود به یک منطقهٔ جغرافیایی خاص دسترسی پیدا کنند |

بر اساس جهت ترافیک، Proxy به دو دستهٔ اصلی تقسیم می‌شود:

- **Forward Proxy**: از طرف کلاینت‌های داخلی عمل می‌کند و هویت کلاینت را از سرورهای خارجی پنهان می‌کند (سناریوی توصیف‌شده در بالا).
- **Reverse Proxy**: در مقابل یک یا چند سرور داخلی قرار می‌گیرد و درخواست‌های ورودی از اینترنت را از طرف آن سرورها دریافت و مدیریت می‌کند؛ در این حالت هویت و ساختار سرورهای داخلی از دید کاربران خارجی پنهان می‌ماند.

| ویژگی | Forward Proxy | Reverse Proxy |
|---|---|---|
| از طرف چه کسی عمل می‌کند | کلاینت‌های داخلی | سرورهای داخلی |
| چه چیزی را پنهان می‌کند | هویت کلاینت از دید اینترنت | هویت و ساختار سرور از دید اینترنت |
| مکان استقرار معمول | لبهٔ شبکهٔ داخلی، رو به اینترنت | جلوی مزرعهٔ سرور (Server Farm)، رو به اینترنت |

یکی از سردرگمی‌های رایج، تفاوت Proxy Server با NAT است؛ هر دو نوعی «تغییر آدرس در مسیر» انجام می‌دهند اما در لایه‌ای کاملاً متفاوت:

| ویژگی | NAT (روی Router) | Proxy Server |
|---|---|---|
| لایهٔ عملکرد | Layer 3/4 (ترجمهٔ آدرس IP و پورت) | Layer 7 (آگاه از محتوای درخواست، مانند URL) |
| آگاهی از محتوا | ندارد؛ فقط سرآیند بسته را تغییر می‌دهد | دارد؛ می‌تواند بر اساس URL یا نوع محتوا تصمیم بگیرد |
| قابلیت Caching | ندارد | دارد |
| شفافیت برای کاربر | کاملاً شفاف و بدون نیاز به تنظیم در سطح برنامه | گاهی نیازمند تنظیم صریح آدرس Proxy در مرورگر یا سیستم‌عامل است |

> نکتهٔ آزمون: اگر گزینه‌ای در سؤال به «Caching» یا «URL Filtering» اشاره کند، پاسخ به‌احتمال زیاد Proxy Server است، نه NAT؛ NAT هرگز محتوای برنامه را بررسی نمی‌کند.

### Load Balancer

Load Balancer دستگاه یا راهکار نرم‌افزاری است که ترافیک ورودی را میان چندین سرور Backend توزیع می‌کند تا هیچ سروری به‌تنهایی دچار اضافه‌بار نشود و کارایی کلی سیستم بهینه بماند.

| مزیت (Benefit) | توضیح |
|---|---|
| Traffic Distribution | بار را میان چند سرور پخش می‌کند تا از اضافه‌بار جلوگیری شود |
| High Availability | در صورت از کار افتادن یک سرور، سایر سرورها جایگزین آن می‌شوند |
| Scalability | افزودن یا حذف سرور بر اساس نیاز، به‌سادگی امکان‌پذیر است |
| Faster Response | درخواست‌ها به سمت سریع‌ترین یا کم‌مشغول‌ترین سرور هدایت می‌شوند |

سه الگوریتم رایج توزیع بار عبارت‌اند از:

- **Round Robin**: درخواست‌ها به‌صورت متوالی و به نوبت میان سرورها توزیع می‌شوند، بدون در نظر گرفتن بار فعلی هرکدام.
- **Least Connections**: هر درخواست جدید به سروری فرستاده می‌شود که کمترین تعداد اتصال فعال را در آن لحظه دارد.
- **IP Hash**: سرور مقصد بر اساس یک تابع هش از آدرس IP کلاینت تعیین می‌شود؛ این روش تضمین می‌کند که یک کاربر مشخص همواره (تا زمانی که تعداد سرورها ثابت بماند) به همان سرور هدایت شود، که برای حفظ Session بدون نیاز به هماهنگی بین سرورها مفید است.

هیچ RFC رسمی و واحدی الگوریتم‌های توزیع بار را استاندارد نکرده است؛ این الگوریتم‌ها عمدتاً پیاده‌سازی‌های خاص هر محصول (مانند HAProxy یا NGINX) یا هر Vendor هستند، هرچند مفاهیم زیرساختی آن‌ها (مانند Health Check دوره‌ای، معمولاً هر ۵ تا ۱۰ ثانیه، برای تشخیص سرورهای از کار افتاده) در عمل بسیار مشابه‌اند.

Load Balancer از این جهت که هر دو نوعی «واسطه‌گری در مسیر ترافیک» انجام می‌دهند، گاهی با Reverse Proxy اشتباه گرفته می‌شود:

| ویژگی | Reverse Proxy (خالص) | Load Balancer |
|---|---|---|
| هدف اصلی | پنهان‌سازی و مدیریت دسترسی به یک یا چند سرور | توزیع بار میان چندین نمونهٔ (Replica) یکسان از یک سرویس |
| تصمیم‌گیری بر مبنای | معمولاً مسیر URL یا نام میزبان (Host Header) | معیارهای بار، تعداد اتصال یا آدرس IP کلاینت |
| نیاز به چند سرور همسان | خیر، می‌تواند جلوی یک سرور تنها باشد | بله، فلسفهٔ وجودی آن وجود چند سرور Backend است |

> نکتهٔ عملی: در عمل، بسیاری از محصولات مانند NGINX یا HAProxy همزمان قابلیت Reverse Proxy و Load Balancer را ارائه می‌دهند؛ تفکیک این دو مفهوم بیشتر برای درک دقیق «چرا» از این ابزار استفاده می‌شود اهمیت دارد، نه برای انتخاب محصول متفاوت.

### Packet Shaper (Traffic Shaper)

Packet Shaper (یا Traffic Shaper) دستگاه یا راهکار نرم‌افزاری است که ترافیک شبکه را تحلیل، کنترل و اولویت‌بندی می‌کند تا مصرف پهنای باند بهینه شده و برنامه‌های حساس (مانند VoIP یا تماس تصویری) حتی زیر بار سنگین شبکه، به‌درستی و بدون افت کیفیت اجرا شوند.

| مزیت (Benefit) | توضیح |
|---|---|
| Improves key app performance | تضمین می‌کند VoIP، کنفرانس یا ابزارهای داخلی سازمان، پهنای باند لازم را دریافت کنند |
| Prevents link congestion | از اشغال کامل پهنای باند لینک توسط دانلودهای حجیم یا استریم جلوگیری می‌کند |
| Enforces user policies | کاربران یا گروه‌ها را بر اساس سرعت، بازهٔ زمانی یا نوع سرویس محدود می‌کند |
| Enables QoS strategies | راهبردهای QoS را برای کیفیت تجربهٔ کاربر پیاده‌سازی می‌کند |

مکانیزم فنی که Packet Shaper برای اولویت‌بندی از آن استفاده می‌کند معمولاً بر پایهٔ **DiffServ** است؛ در این مدل (تعریف‌شده در RFC 2474 و RFC 2475) یک فیلد شش‌بیتی به نام **DSCP (Differentiated Services Code Point)** در سرآیند IP قرار می‌گیرد که بستهٔ داده را به یکی از کلاس‌های اولویت (مانند EF یا Expedited Forwarding با مقدار ۴۶، که معمولاً برای ترافیک صوتی VoIP رزرو می‌شود) دسته‌بندی می‌کند.

برای مثال، در بسیاری از پیاده‌سازی‌های عملی QoS روی یک لینک WAN، رویکرد رایج آن است که بخشی مشخص از پهنای باند کل لینک (برای نمونه ۲۰ تا ۳۰ درصد) به‌طور تضمینی (Guaranteed) برای ترافیک صدا و کنفرانس رزرو شود، تا حتی در اوج ازدحام شبکه، کیفیت تماس افت نکند؛ این رویکرد در پیاده‌سازی سیسکو با عنوان **CBWFQ (Class-Based Weighted Fair Queuing)** شناخته می‌شود.

از آنجا که هدف Load Balancer (توزیع بار میان چند سرور) با هدف Packet Shaper (کنترل و اولویت‌بندی نوع ترافیک روی یک لینک) گاهی در یک جمله خلاصه می‌شوند («بهینه‌سازی عملکرد شبکه»)، تفکیک دقیق این دو نیز اهمیت دارد:

| ویژگی | Load Balancer | Packet Shaper |
|---|---|---|
| سطح تصمیم‌گیری | کدام سرور درخواست را پاسخ دهد | کدام بسته زودتر یا با اولویت بالاتر ارسال شود |
| مسئلهٔ اصلی که حل می‌کند | اضافه‌بار روی یک سرور خاص | اشباع پهنای باند یک لینک مشترک |
| واحد تصمیم‌گیری | درخواست یا اتصال (Connection) | بسته (Packet) بر اساس نوع ترافیک |

> نکتهٔ آزمون: اگر سؤال دربارهٔ حفظ کیفیت تماس VoIP هنگام دانلود حجیم فایل توسط کاربران دیگر باشد، پاسخ صحیح Packet Shaper (یا QoS) است، نه Load Balancer؛ Load Balancer هیچ ارتباطی با اولویت‌بندی نوع ترافیک ندارد.

## بخش عملی: مشاهده و پیکربندی این تجهیزات در لینوکس

هرچند اغلب دستگاه‌های بالا در دنیای واقعی سخت‌افزارهای اختصاصی هستند، می‌توان مفاهیم اصلی آن‌ها را با ابزارهای رایج لینوکس مشاهده یا حتی شبیه‌سازی کرد.

### مشاهدهٔ جدول MAC و ARP (مفهوم Switch و Router)

```bash
# نمایش جدول ARP (نگاشت IP به MAC) که Router برای تحویل محلی از آن استفاده می‌کند
$ ip neigh show
192.168.1.1 dev eth0 lladdr 00:1a:2b:3c:4d:5e REACHABLE
192.168.1.20 dev eth0 lladdr 00:aa:bb:cc:dd:ee STALE

# نمایش پورت‌ها و وضعیت لینک (شبیه بررسی وضعیت پورت روی یک Switch مدیریت‌شده)
$ ip link show eth0
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP
    link/ether 08:00:27:aa:bb:cc brd ff:ff:ff:ff:ff:ff
```

### ساخت یک Bridge نرم‌افزاری (مفهوم Bridge/Switch)

```bash
# ساخت یک اینترفیس Bridge و افزودن دو اینترفیس فیزیکی به آن،
# دقیقاً مشابه کاری که یک Switch دو‌پورته (Bridge) در سطح سخت‌افزار انجام می‌دهد
$ sudo ip link add name br0 type bridge
$ sudo ip link set eth1 master br0
$ sudo ip link set eth2 master br0
$ sudo ip link set br0 up
$ bridge link show
3: eth1 state forwarding priority 32 cost 100 master br0
4: eth2 state forwarding priority 32 cost 100 master br0
```

### فیلترکردن ترافیک با nftables (مفهوم Firewall)

```bash
# مسدودکردن یک آدرس IP مخرب مشخص (معادل نمونهٔ Bad IP که در بخش Firewall توضیح داده شد)
$ sudo nft add rule inet filter input ip saddr 203.0.113.66 drop

# مشاهدهٔ قوانین فعلی، معادل بررسی Rule Base یک Firewall
$ sudo nft list ruleset
table inet filter {
    chain input {
        type filter hook input priority 0; policy accept;
        ip saddr 203.0.113.66 drop
    }
}
```

### شبیه‌سازی Traffic Shaping با tc (مفهوم Packet Shaper و QoS)

```bash
# محدودکردن پهنای باند خروجی یک اینترفیس به ۱۰ مگابیت بر ثانیه
# و رزرو اولویت برای ترافیک با DSCP معادل EF (صدا)
$ sudo tc qdisc add dev eth0 root handle 1: htb default 30
$ sudo tc class add dev eth0 parent 1: classid 1:10 htb rate 2mbit ceil 2mbit
$ sudo tc class add dev eth0 parent 1: classid 1:30 htb rate 8mbit ceil 10mbit
$ tc -s class show dev eth0
class htb 1:10 root prio 0 rate 2Mbit ceil 2Mbit burst 1600b cburst 1600b
class htb 1:30 root prio 0 rate 8Mbit ceil 10Mbit burst 1600b cburst 1600b
```

### اجرای یک Proxy Server ساده (مفهوم Proxy)

```bash
# نصب و اجرای Squid به‌عنوان یک Forward Proxy روی پورت پیش‌فرض 3128
$ sudo apt install squid --break-system-packages 2>/dev/null; sudo systemctl start squid
$ curl -x http://127.0.0.1:3128 http://example.com -I
HTTP/1.1 200 OK
Via: 1.1 proxy-host (squid/5.7)
X-Cache: MISS from proxy-host
```

### توزیع بار ساده با HAProxy (مفهوم Load Balancer)

```bash
# بخشی از فایل پیکربندی HAProxy با الگوریتم Round Robin میان دو سرور Backend
backend web_servers
    balance roundrobin
    server web1 10.0.0.11:80 check
    server web2 10.0.0.12:80 check

$ sudo systemctl reload haproxy
$ echo "show stat" | sudo socat stdio /run/haproxy/admin.sock | cut -d, -f1,2,18
# pxname,svname,status
web_servers,web1,UP
web_servers,web2,UP
```

## جمع‌بندی

| دستگاه | لایهٔ اصلی OSI | مبنای تصمیم‌گیری | نقش اصلی |
|---|---|---|---|
| Hub | Layer 1 | ندارد (تکرار سیگنال) | اتصال فیزیکی چند دستگاه با یک Collision Domain مشترک |
| Bridge | Layer 2 | آدرس MAC | تقسیم یک Collision Domain بزرگ به چند Collision Domain کوچک‌تر |
| Switch | Layer 2 (و Layer 3 در نوع Multilayer) | آدرس MAC (و IP در نوع Layer 3) | اتصال هوشمند دستگاه‌های یک LAN با Collision Domain جداگانه به‌ازای هر پورت |
| Router | Layer 3 | آدرس IP | اتصال و مسیریابی میان شبکه‌های مجزا، مرزبندی Broadcast Domain |
| Wireless Access Point | Layer 2 | آدرس MAC / SSID | گسترش پوشش شبکهٔ سیمی به دستگاه‌های بی‌سیم |
| Firewall | Layer 4 | 5-Tuple (IP/Port/Protocol) | کنترل عبور ترافیک بر اساس قواعد امنیتی |
| Next-Generation Firewall | تا Layer 7 | 5-Tuple + محتوای بسته | فیلترکردن پیشرفته با آگاهی از برنامه و محتوا |
| IDS | Layer 3 تا 7 (رصد) | امضا/الگوی ترافیک مخرب | شناسایی و هشدار بدون مسدودسازی |
| IPS | Layer 3 تا 7 (Inline) | امضا/الگوی ترافیک مخرب | شناسایی و مسدودسازی بلادرنگ |
| Proxy Server | Layer 7 | URL/محتوای درخواست | واسطه‌گری، پنهان‌سازی هویت، Caching |
| Load Balancer | Layer 4/7 | بار سرور، اتصال، IP کلاینت | توزیع ترافیک میان چند سرور Backend |
| Packet Shaper | Layer 3/4 (با آگاهی از نوع ترافیک) | DSCP/نوع برنامه | اولویت‌بندی و کنترل مصرف پهنای باند |
