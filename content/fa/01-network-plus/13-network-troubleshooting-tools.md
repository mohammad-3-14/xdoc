# ابزارهای عیب‌یابی شبکه

عیب‌یابی شبکه فرآیندی لایه‌به‌لایه است: از بررسی اتصال ساده با یک درخواست ICMP آغاز می‌شود، به ترسیم مسیر عبور بسته‌ها می‌رسد، سپس پیکربندی آداپتور شبکه، قوانین فایروال، وضعیت DNS، اتصالات فعال و در نهایت محتوای واقعی بسته‌ها را زیر ذره‌بین می‌برد. آنچه در ادامه می‌آید، مجموعه‌ای از ابزارهای خط‌فرمان است که هر یک به یکی از این لایه‌ها می‌پردازد؛ برای هر ابزار، پیام‌ها یا دستورات رایج، معنای آن‌ها، علت احتمالی بروز و راه‌حل پیشنهادی آورده شده است.

## ۱. Ping Tool

**تعریف:** ابزار ping یک ابزار پایهٔ تشخیص شبکه است که برای آزمودن دسترس‌پذیری یک میزبان در شبکهٔ IP و اندازه‌گیری زمان رفت‌وبرگشت (Round-Trip Time) پیام از مبدأ تا مقصد استفاده می‌شود.

| پیام | معنا | علت محتمل | راه‌حل |
|---|---|---|---|
| `Reply from [IP]: Time=xxms TTL=yy` | میزبان در دسترس است و پاسخ ICMP Echo دریافت شده. | هدف آنلاین و مسیر شبکه سالم است. | از TTL برای تخمین تعداد hop استفاده کنید (۱۲۸ در ویندوز، ۶۴ در لینوکس). زمان کمتر از ۱۰ میلی‌ثانیه در LAN عالی است. |
| `Request Timed Out` | پاسخی به درخواست ICMP Echo دریافت نشد. | میزبان خاموش است؛ ICMP توسط فایروال مسدود شده؛ مسیریابی یا مسیر شبکه دچار اختلال است. | اگر گیت‌وی پاسخ می‌دهد ولی هدف نه، مشکل احتمالاً فراتر از Layer 3 است. |
| `Destination Host Unreachable` | دستگاه محلی یا گیت‌وی نمی‌داند چگونه به مقصد برسد. | مسیر معتبری وجود ندارد؛ Subnet Mask یا Default Gateway اشتباه است. | زمانی رخ می‌دهد که میزبان به شبکهٔ دیگر مسیری ندارد و گیت‌وی‌ای تعریف نشده است. |
| `General Failure` | حتی ارسال درخواست ICMP هم آغاز نشد. | آداپتور شبکه غیرفعال است؛ IP تخصیص نیافته؛ آنتی‌ویروس یا فایروال تداخل ایجاد کرده. | بررسی کنید اینترفیس فعال و پیکربندی معتبر دارد. با دسترسی مدیر (Admin) نیز آزمایش کنید. |
| Ping به دامنه شکست می‌خورد ولی روی IP کار می‌کند | Resolve شدن DNS مشکل دارد. | تنظیمات DNS اشتباه؛ سرور DNS در دسترس نیست؛ خرابی سرویس DNS. | با `nslookup domain.com` رفتار DNS را تأیید کنید. |
| پاسخ‌های نامنظم / تأخیر زیاد | شبکه ناپایدار است یا بسته‌ها گم می‌شوند. | تداخل Wi-Fi؛ نویز روی کابل؛ سوییچ یا روتر بیش‌ازحد بارگذاری‌شده. | با `ping -t` یا `ping -n 50` نوسان تأخیر و افت بسته را رصد کنید. |

```bash
$ ping 192.168.172.85

Pinging 192.168.172.85 with 32 bytes of data:
Reply from 192.168.172.85: bytes=32 time=6ms TTL=64
Reply from 192.168.172.85: bytes=32 time=6ms TTL=64
Reply from 192.168.172.85: bytes=32 time=6ms TTL=64
Reply from 192.168.172.85: bytes=32 time=7ms TTL=64

Ping statistics for 192.168.172.85:
    Packets: Sent = 4, Received = 4, Lost = 0 (0% loss),
Approximate round trip times in milli-seconds:
    Minimum = 6ms, Maximum = 7ms, Average = 6ms
```

نمونهٔ شکست Resolve دامنه:

```bash
$ ping ofran
ping: cannot resolve ofran: Unknown host
```

## ۲. Traceroute / Tracert Tool

**تعریف:** ابزار traceroute (در ویندوز با نام tracert) مسیری را که بسته‌ها از دستگاه مبدأ تا آدرس IP مقصد طی می‌کنند، با افزایش تدریجی مقدار TTL ردیابی می‌کند. این ابزار برای شناسایی حلقه‌های مسیریابی (Routing Loop)، تأخیرها یا افت بسته در طول مسیر شبکه به کار می‌رود.

| پیام/رفتار | معنا | علت محتمل | راه‌حل |
|---|---|---|---|
| `Hop N: IP Address - time=xx ms` | بسته با موفقیت به آن hop (روتر) رسیده است. | مسیر طبیعی است؛ روتر به پیام‌های ICMP TTL Expired پاسخ می‌دهد. | تأخیر هر hop را تحلیل کنید و به دنبال جهش‌های ناگهانی بگردید. |
| `Hop N: * * * Request timed out` | پاسخ ICMP TTL Expired از آن hop دریافت نشد. | ICMP توسط فایروال مسدود شده؛ hop از کار افتاده؛ روتر پاسخ نمی‌دهد. | اگر گاه‌به‌گاه باشد نادیده بگیرید؛ Timeout مداوم نشانهٔ مشکل در همان hop یا hop بعدی است. |
| تأخیر طولانی بین hopها | تأخیر بالا در همان روتر یا بعد از آن. | ازدحام پهنای باند، تأخیر پردازشی، مشکلات مسیریابی. | متریک مسیر، بار شبکه یا خطای اینترفیس همان گره را بررسی کنید. |
| متوقف‌ماندن TTL پیش از رسیدن به مقصد | حلقهٔ مسیریابی یا Black Hole در شبکه. | حلقه در جدول مسیریابی یا حذف خاموش بسته توسط فایروال. | از `mtr` یا traceroute گسترده برای تأیید مسیرهای پویا استفاده کنید. |
| نرسیدن به hop نهایی | بسته‌ها هرگز به مقصد نمی‌رسند. | مسیر پس از آخرین روتر پاسخ‌گو قطع شده است. | روتر نهایی را پینگ کنید یا از Reverse Traceroute برای آزمون در جهت مخالف استفاده کنید. |
| مسیر متفاوت در هر اجرا | رفتار Load Balancing یا مسیریابی پویا. | مسیریابی چندمسیرهٔ هم‌هزینه (ECMP)، تغییر مسیر توسط ISP. | چند بار traceroute اجرا کنید و hopهای ثابت و متغیر را مشاهده کنید. |

```bash
$ traceroute 192.168.172.164

1  192.168.172.66 (192.168.172.66)  0.585 ms  0.565 ms  0.560 ms
2  192.168.172.164 (192.168.172.164)  33.205 ms  5.865 ms

erfanbagheriavval@Erfans-MacBook-Pro ~ % traceroute asf198.iz
traceroute: unknown host asf198.iz
```

> **نکتهٔ عملی:** خطای «unknown host» در traceroute دقیقاً مشابه همین خطا در ping، ناشی از شکست Resolve شدن نام دامنه است، نه مشکل مسیریابی؛ پیش از عیب‌یابی مسیر، ابتدا باید از سالم بودن DNS با `nslookup` مطمئن شد.

## ۳. Ipconfig / Ifconfig Tool

**تعریف:** ipconfig (در ویندوز) و ifconfig (در لینوکس/یونیکس) ابزارهای خط‌فرمانی هستند که برای مشاهده و مدیریت پیکربندی اینترفیس شبکه در سیستم‌عامل به کار می‌روند.

| دستور | هدف/توضیح | نمونهٔ عیب‌یابی |
|---|---|---|
| `ipconfig` یا `ifconfig` | نمایش آدرس IP، Subnet Mask، Default Gateway و آدرس MAC. | بررسی اینکه آیا دستگاه IP معتبر گرفته و DHCP فعال است. |
| `ipconfig /all` | نمایش اطلاعات کامل شامل DNS، Lease مربوط به DHCP، MAC و پیکربندی کامل. | تشخیص اینکه دستگاه از DHCP استفاده می‌کند یا IP استاتیک. |
| `ipconfig /release` | آزادسازی آدرس IP فعلی تخصیص‌یافته توسط DHCP. | زمانی مفید است که IP نادرست باشد یا نیاز به دریافت مجدد باشد. |
| `ipconfig /renew` | درخواست یک آدرس IP جدید از سرور DHCP. | رفع مشکلات مربوط به Lease منقضی یا گم‌شده. |
| `ifconfig eth0` یا `ifconfig -a` | نمایش وضعیت کامل اینترفیس (در لینوکس). | بررسی فعال بودن اینترفیس یا داشتن IP تخصیص‌یافته. |
| `ifconfig eth0 down/up` | غیرفعال/فعال کردن اینترفیس شبکه. | برای ریست دستی اینترفیس یا آزمایش استفاده می‌شود. |
| IP نادرست: `169.254.x.x` | دستگاه نتوانسته از DHCP آدرس بگیرد و خودش آدرس APIPA تخصیص داده. | نشان‌دهندهٔ در دسترس نبودن یا کار نکردن سرور DHCP است. |
| ناهم‌خوانی آدرس MAC | آدرس MAC فیزیکی با مقدار موردانتظار یا تنظیمات شبکه متفاوت است. | بررسی احتمال Spoofing یا خطای پیکربندی دستی. |

```bash
C:\Users\erfan> ipconfig /all

Wireless LAN adapter Wi-Fi:
   Connection-specific DNS Suffix  . :
   IPv4 Address. . . . . . . . . . . : 192.168.172.146
   Subnet Mask . . . . . . . . . . . : 255.255.255.0
   Default Gateway . . . . . . . . . : 192.168.172.66
```

```bash
$ ifconfig en0
en0: flags=8863<UP,BROADCAST,SMART,RUNNING,SIMPLEX,MULTICAST> mtu 1500
   status: active
```

## ۴. Iptables Tool

**تعریف:** iptables ابزاری خط‌فرمانی است که در سیستم‌های لینوکس برای پیکربندی فایروال داخلی هستهٔ سیستم‌عامل استفاده می‌شود. با آن می‌توان قوانینی برای کنترل ترافیک ورودی، خروجی و عبوری بر اساس IP، پروتکل، پورت و موارد دیگر تعریف کرد.

| دستور | هدف/توضیح | کاربرد در عیب‌یابی |
|---|---|---|
| `iptables -L` | فهرست تمام قوانین فایروال فعلی. | بررسی اینکه آیا پورت خاصی مسدود شده است. |
| `iptables -A INPUT -p tcp --dport 80 -j ACCEPT` | مجاز کردن ترافیک TCP ورودی روی پورت ۸۰ (HTTP). | زمانی استفاده می‌شود که سرویس وب اجرا می‌شود اما از بیرون در دسترس نیست. |
| `iptables -A INPUT -s [IP] -j DROP` | مسدود کردن کل ترافیک ورودی از یک آدرس IP خاص. | برای مسدودسازی IPهای مشکوک، مثلاً هنگام حملهٔ DoS. |
| `iptables -F` | حذف (Flush) تمام قوانین فعلی. | در محیط آزمایشگاهی مفید، اما در محیط Production خطرناک است چون کل محافظت را حذف می‌کند. |
| `iptables -A OUTPUT -p udp --dport 53 -j ACCEPT` | مجاز کردن درخواست‌های خروجی DNS روی پورت ۵۳. | کمک به رفع مشکلات مربوط به تفکیک نام دامنه (Resolve نشدن). |
| سرویس ناگهان مسدود/غیرقابل‌دسترس شده | ممکن است ناشی از یک قانون پیکربندی‌شدهٔ اشتباه باشد که ترافیک ضروری را مسدود کرده. | از `iptables -L -n -v` برای بررسی ترتیب قوانین، تعداد برخورد (Hit Count) و مسدودی‌ها استفاده کنید. |

## ۵. Nslookup Tool

**تعریف:** nslookup یکی از ضروری‌ترین ابزارهای خط‌فرمان برای آزمودن عملکرد DNS است. این ابزار کمک می‌کند مشخص شود آیا یک نام دامنه به‌درستی به یک آدرس IP تبدیل (Resolve) می‌شود، و امکان تحلیل رکوردهای DNS را نیز فراهم می‌آورد.

| دستور | هدف/توضیح | نکتهٔ آموزشی/مثال |
|---|---|---|
| `nslookup google.com` | بررسی اینکه google.com به چه آدرس IPای Resolve می‌شود. | اگر IP برگردانده شود یعنی DNS کار می‌کند؛ در صورت خطا، مشکل از تنظیمات یا سرویس DNS است. |
| `nslookup` سپس `server 8.8.8.8` | تغییر سرور DNS مورد استفاده به DNS گوگل برای آزمایش. | برای تشخیص اینکه مشکل از DNS محلی است یا یک مشکل عمومی در Resolve شدن. |
| `nslookup` سپس `set type=MX` | نمایش رکوردهای Mail Exchange یک دامنه. | برای آزمایش تنظیمات ایمیل دامنه، مثلاً `nslookup MX google.com`. |
| `nslookup` سپس `set type=NS` | فهرست Name Serverهای مرتبط با یک دامنه. | کمک به تشخیص اینکه کدام DNS Authority مسئول است — مفید برای عیب‌یابی انتقال (Transfer). |
| `nslookup` سپس `set type=TXT` | نمایش رکوردهای TXT (مانند SPF، DKIM). | رایج در بررسی احراز هویت ایمیل و تنظیمات امنیتی. |
| `DNS request timed out` | پاسخی از سرور DNS دریافت نشد. | سرور DNS در دسترس نیست، پورت ۵۳ مسدود شده، یا قطعی کلی اینترنت رخ داده. |
| Resolve نادرست یا ناقص IP | دامنه به آدرس IP اشتباه یا قدیمی Resolve می‌شود. | ممکن است نشان‌دهندهٔ Cache قدیمی DNS یا حملهٔ احتمالی DNS Poisoning باشد. |

```bash
$ nslookup ravinacademy.com

Server:   8.8.8.8
Address:  8.8.8.8#53

Non-authoritative answer:
Name:    ravinacademy.com
Address: 188.40.96.143
```

## ۶. Netstat Tool

**تعریف:** netstat ابزاری خط‌فرمانی است که اطلاعاتی دربارهٔ اتصالات فعال شبکه، پورت‌های در حال گوش‌دادن (Listening)، آمار پروتکل‌ها و جدول مسیریابی ارائه می‌دهد. این ابزار برای عیب‌یابی مشکلات اتصال، شناسایی پورت‌های باز و ردیابی اتصالات مشکوک ضروری است.

| دستور | هدف/توضیح | کاربرد/نکتهٔ آموزشی |
|---|---|---|
| `netstat -an` | فهرست تمام اتصالات فعال و پورت‌های Listening به‌صورت عددی. | بررسی سریع اینکه آیا پورت خاصی باز است و چه IPهایی متصل‌اند. |
| `netstat -ano` | افزودن شناسهٔ فرآیند (PID) به هر اتصال. | کمک به شناسایی برنامه‌ای که از یک پورت خاص استفاده می‌کند، در کنار Task Manager. |
| `netstat -s` | نمایش آمار هر پروتکل (TCP، UDP، ICMP و ...). | تشخیص مشکلات سطح پروتکل مانند افت بستهٔ زیاد یا نرخ خطای بالا. |
| `netstat -r` | نمایش جدول مسیریابی سیستم. | عیب‌یابی مشکلات گیت‌وی یا پیکربندی چند-اینترفیسی. |
| `ESTABLISHED` | نشان‌دهندهٔ یک اتصال موفق TCP. | حالت طبیعی برای برنامه‌های فعال، مثلاً مرورگری متصل به یک سایت. |
| `LISTENING` | یک پورت باز است و منتظر اتصالات ورودی. | برای تأیید فعال بودن یک سرویس/سرور (مثل SSH یا FTP). |
| `TIME_WAIT` / `CLOSE_WAIT` | نشان‌دهندهٔ نشست‌های TCP خاتمه‌یافته اما هنوز کاملاً بسته‌نشده. | می‌تواند رفتار طبیعی TCP باشد یا نشانهٔ نشست‌های باز بیش‌ازحد ناشی از پیکربندی نادرست. |

## ۷. Arp Tool

**تعریف:** دستور arp برای مشاهده و مدیریت ARP Cache یک سیستم استفاده می‌شود — جدولی که آدرس‌های IP را به آدرس‌های MAC در شبکهٔ محلی نگاشت می‌کند. این ابزار به عیب‌یابی مشکلات اتصال محلی کمک می‌کند و می‌تواند تهدیدات امنیتی مانند ARP Spoofing را نیز آشکار سازد.

| دستور | هدف/توضیح | کاربرد/نکته |
|---|---|---|
| `arp -a` | نمایش جدول فعلی ARP (نگاشت IP به MAC). | بررسی اینکه آیا یک دستگاه محلی برای سیستم شناخته‌شده است یا در LAN پاسخ می‌دهد. |
| `arp -d [IP address]` | حذف یک ورودی خاص از ARP Cache. | اجبار به ارسال درخواست ARP جدید برای تشخیص نگاشت‌های قدیمی یا نادرست. |
| `MAC address = 00-00-00-00-...` | نشان‌دهندهٔ عدم دریافت پاسخ ARP برای آن IP. | هدف ممکن است آفلاین باشد، توسط فایروال مسدود شده، یا به ARP پاسخ ندهد. |
| چند IP → یک MAC مشترک | نشان‌دهندهٔ آنکه یک دستگاه چند IP دارد یا احتمال فعالیت ARP Spoofing وجود دارد. | در آموزش‌های امنیتی برای معرفی مفاهیم ARP Poisoning و حملهٔ Man-in-the-Middle استفاده می‌شود. |

## ۸. Lsof Tool

**تعریف:** در لینوکس تقریباً همه‌چیز به‌مثابهٔ یک فایل در نظر گرفته می‌شود — از جمله اتصالات شبکه. دستور lsof کمک می‌کند مشخص شود چه فایل‌ها، پورت‌ها و اتصالاتی درحال‌حاضر در حال استفاده‌اند و کدام فرآیند از آن‌ها استفاده می‌کند.

| دستور | هدف/توضیح | کاربرد/مثال |
|---|---|---|
| `lsof -i` | نمایش تمام اتصالات شبکهٔ فعال فعلی. | شناسایی اینکه کدام برنامه‌ها یا فرآیندها از شبکه استفاده می‌کنند. |
| `lsof -i :80` | فهرست تمام فرآیندهایی که از پورت ۸۰ استفاده می‌کنند. | بررسی اینکه آیا وب‌سرور در حال اجراست یا برنامهٔ دیگری آن پورت را اشغال کرده. |
| `lsof -iTCP -sTCP:LISTEN` | نمایش تنها پورت‌های TCP در حالت Listening. | مناسب برای ممیزی اینکه چه سرویس‌هایی آمادهٔ دریافت اتصال ورودی هستند. |
| `lsof /path/to/file` | نمایش اینکه کدام فرآیند از یک فایل خاص استفاده می‌کند. | کمک به توضیح اینکه چرا یک فایل قابل حذف نیست — هنوز توسط یک فرآیند در حال استفاده است. |
| `lsof -u username` | فهرست تمام فایل‌ها و فعالیت شبکهٔ یک کاربر خاص. | مفید برای مانیتورینگ اختصاصی کاربر یا شناسایی رفتار مشکوک. |

## ۹. Tcpdump Tool

ابزارهایی مانند ping و traceroute می‌گویند آیا چیزی کار می‌کند یا نه؛ اما tcpdump دقیقاً نشان می‌دهد در پشت‌صحنه چه اتفاقی در حال رخ‌دادن است. tcpdump مانند یک میکروسکوپ برای ترافیک شبکه عمل می‌کند: بسته‌ها را به‌صورت بلادرنگ (Real-time) و مستقیماً از اینترفیس شبکه ثبت و نمایش می‌دهد — بدون هیچ رابط گرافیکی، فقط قدرت خام.

| دستور tcpdump | توضیح فیلتر | کاربرد/سناریو |
|---|---|---|
| `tcpdump port 80` | ثبت تمام ترافیک روی پورت HTTP (۸۰). | مانیتورینگ درخواست‌های مرورگر به/از یک وب‌سرور محلی یا راه‌دور. |
| `tcpdump dst port 53` | ثبت بسته‌های مقصد پورت ۵۳ (درخواست‌های DNS). | تأیید اینکه درخواست‌های DNS به سرور DNS می‌رسند. |
| `tcpdump src port 53` | ثبت بسته‌های خروجی از پورت ۵۳ (پاسخ‌های DNS). | بررسی اینکه آیا سرور DNS به‌درستی پاسخ می‌دهد. |
| `tcpdump host 192.168.1.10` | ثبت تمام ترافیک به/از یک IP خاص. | مانیتورینگ فعالیت یا رفتار یک کلاینت خاص در شبکه. |
| `tcpdump src host 192.168.1.10` | ثبت فقط بسته‌های خروجی از یک میزبان. | تحلیل اینکه آیا یک دستگاه در حال ارسال داده به بیرون است (مثلاً آپلود فایل). |
| `tcpdump dst host 192.168.1.1 and port 443` | ثبت ترافیک HTTPS به یک سرور خاص. | تأیید صحت دسترسی HTTPS به گیت‌وی یا سرور امن. |
| `tcpdump -i eth0 tcp` | ثبت فقط ترافیک TCP روی اینترفیس eth0. | فیلترینگ پایه برای سرویس‌هایی مانند HTTP، FTP یا SSH. |
| `tcpdump udp port 67 or udp port 68` | ثبت ترافیک DHCP (پورت‌های ۶۷ و ۶۸). | بررسی اینکه آیا کلاینت IP دریافت می‌کند و تحلیل تبادل DHCP. |
| `tcpdump -nn -v -X port 21` | ثبت جزئی ترافیک FTP همراه با نمایش محتوای بسته (Payload). | بررسی اینکه آیا نام‌کاربری/رمز عبور به‌صورت متن ساده و ناامن ارسال می‌شود. |
| `tcpdump 'tcp[tcpflags] & tcp-syn != 0'` | ثبت تنها بسته‌های TCP SYN (آغاز اتصال). | مفید برای شمارش تلاش‌های اتصال یا شناسایی حملهٔ SYN Flood. |
| `tcpdump 'icmp'` | ثبت بسته‌های ICMP (مانند ping). | تشخیص دسترس‌پذیری ICMP بین دو میزبان یا شناسایی پاسخ‌های Ping ازدست‌رفته. |

```bash
$ tcpdump -i en0 icmp -nn
tcpdump: verbose output suppressed, use -v[v]... for full protocol decode
listening on en0, link-type EN10MB (Ethernet), snapshot length 524288 bytes
23:31:16.051887 IP 192.168.172.66 > 192.168.172.85: ICMP net 8.8.8.8 unreachable
23:31:17.689081 IP 192.168.172.66 > 192.168.172.85: ICMP net 8.8.8.8 unreachable
23:31:19.631568 IP 192.168.172.66 > 192.168.172.85: ICMP net 8.8.8.8 unreachable
```

> **نکتهٔ عملی:** در نمونهٔ بالا، خودِ گیت‌وی (`192.168.172.66`) است که پیام `ICMP net unreachable` برای `8.8.8.8` تولید می‌کند؛ یعنی درخواست تا گیت‌وی رسیده، اما گیت‌وی مسیری به سمت اینترنت ندارد — نشانه‌ای مشخص برای عیب‌یابی که مشکل فراتر از دستگاه محلی و در سطح روتر/اتصال بالادستی است.

## ۱۰. Route Tool

| دستور/مفهوم | هدف/توضیح | نکتهٔ آموزشی |
|---|---|---|
| `route print` | نمایش جدول مسیریابی سیستم (IPv4/IPv6). | برای شناسایی مسیرهای پیش‌فرض و عیب‌یابی بلادرنگ مسائل مسیریابی استفاده می‌شود. |
| `route add 10.0.0.0 mask 255.0.0.0 192.168.1.1` | افزودن یک مسیر استاتیک برای شبکهٔ 10.0.0.0/8 از طریق گیت‌وی 192.168.1.1. | آموزش منطق ساب‌نتینگ و نقش گیت‌وی با استفاده از توپولوژی‌های واقعی شبکه. |
| `route add 0.0.0.0 mask 0.0.0.0 192.168.1.1` | تعریف مسیر پیش‌فرض (Default Route). | تأکید بر اینکه این مسیر برای دسترسی به اینترنت ضروری است — بدون آن، هیچ ارتباط بیرونی برقرار نمی‌شود. |
| `route delete 10.0.0.0` | حذف یک مسیر استاتیک خاص از جدول. | مفید هنگام پاک‌سازی مسیرهای اشتباه یا آزمایشی. |
| `route -f` | حذف (Flush) تمام مسیرهای موقت (پویا). | برای مواردی که VPN یا DHCP مسیرهای ناقص یا متناقض باقی می‌گذارند. |
| `ip route show` | دستور مدرن لینوکس برای نمایش جدول مسیریابی. | آشنایی هم‌زمان با روش سنتی و مدرن، برای کار در محیط‌های مختلف. |
| `ip route get 8.8.8.8` | شبیه‌سازی اینکه یک بسته به سمت IP مشخص چگونه مسیریابی می‌شود. | نمایش اینکه کدام اینترفیس و گیت‌وی برای ترافیک خروجی انتخاب می‌شود. |
| Default Route (0.0.0.0/0) | مسیر پیش‌فرض سیستم برای هر مقصد ناشناخته. | اهمیت آن در مسیریابی تمام مقاصد نامشخص — معمولاً ترافیک رو به اینترنت. |
| Metric | اولویت مسیر را تعیین می‌کند؛ مقدار کمتر یعنی اولویت بالاتر. | نمایش چند مسیر هم‌خوان و نحوهٔ انتخاب مسیر با کمترین Metric توسط سیستم. |
| Interface | مشخص می‌کند کدام آداپتور شبکه بسته را ارسال می‌کند. | نمایش تأثیر چند آداپتور (مثلاً Ethernet و Wi-Fi) بر تصمیمات مسیریابی. |

## ۱۱. Telnet Tool

**تعریف:** telnet یک ابزار سادهٔ خط‌فرمان است که امکان اتصال به یک پورت مشخص روی یک آدرس IP یا دامنه را فراهم می‌کند.

| دستور | هدف/توضیح | نکتهٔ آموزشی/سناریوی واقعی |
|---|---|---|
| `telnet 192.168.1.10 80` | اتصال به پورت ۸۰ روی یک وب‌سرور محلی/داخلی. | آزمودن اینکه آیا وب‌سرور داخلی درخواست‌های HTTP را می‌پذیرد. |
| `telnet google.com 443` | تلاش برای اتصال به پورت HTTPS گوگل (۴۴۳). | در صورت شکست اتصال، احتمالاً فایروال یا مسدودی پورت مقصر است. |
| `telnet smtp.mail.com 25` | آزمودن دستی اتصال به یک سرور ایمیل SMTP (پورت ۲۵). | تأیید در دسترس بودن سرور ایمیل خروجی؛ به‌ویژه در شبکه‌های سازمانی کاربرد دارد. |
| موفقیت = صفحهٔ خالی (Black Screen) | اگر ترمینال خالی/سیاه بماند، پورت باز است. | نکتهٔ آموزشی: نبود خطا معمولاً یعنی اتصال موفق در Telnet. |
| شکست = «connection refused» / Timeout | نشان‌دهندهٔ بسته یا غیرقابل‌دسترس بودن پورت است. | می‌تواند به‌دلیل خاموش بودن سرویس، مسدودی توسط فایروال یا IP/نام میزبان اشتباه باشد. |

```bash
$ telnet google.com 80
Trying 142.250.xx.xx...
Connected to google.com.
Escape character is '^]'.
GET / HTTP/1.0

HTTP/1.0 400 Bad Request
Content-Type: text/html; charset=UTF-8

<html>
<head><title>Bad Request</title></head>
<body>
<h1>400 Bad Request</h1>
Your client has issued a malformed or illegal request.
</body>
</html>
Connection closed by foreign host.
```

> **نکتهٔ عملی:** ارسال یک درخواست HTTP خام (حتی ناقص، مثل تنها `GET / HTTP/1.0`) از طریق Telnet روشی سریع برای اطمینان از پاسخ‌گو بودن یک وب‌سرور در سطح لایهٔ کاربرد (Application Layer) است — فراتر از صرفاً باز بودن پورت.

## ۱۲. Netsh Tool

**تعریف:** netsh (مخفف Network Shell) ابزاری خط‌فرمانی در ویندوز است که امکان مشاهده، پیکربندی، ریست و عیب‌یابی تنظیمات شبکه را فراهم می‌کند. این ابزار برای مدیریت پیکربندی IP، اینترفیس‌های شبکه، قوانین فایروال، پروفایل‌های بی‌سیم، تنظیمات پراکسی و موارد دیگر — همه از طریق خط‌فرمان — بسیار کارآمد است.

| دستور | هدف/توضیح | سناریو/کاربرد |
|---|---|---|
| `netsh interface ip show config` | نمایش کامل تنظیمات IP تمام اینترفیس‌های شبکه. | بررسی سریع اطلاعات IP استاتیک یا تخصیص‌یافته توسط DHCP روی همهٔ آداپتورها. |
| `netsh interface ipv4 set address name="Ethernet" static 192.168.1.100 255.255.255.0 192.168.1.1` | تنظیم دستی یک آدرس IP استاتیک برای یک اینترفیس شبکه. | مفید هنگام راه‌اندازی سرورها یا عیب‌یابی مشکلات DHCP. |
| `netsh interface set interface name="Ethernet" admin=disabled` | غیرفعال کردن یک اینترفیس شبکهٔ خاص. | غیرفعال‌سازی موقت یک NIC برای تست یا عیب‌یابی. |
| `netsh winsock reset` | ریست کردن Winsock Catalog. | رفع بسیاری از مشکلات اینترنت ناشی از خرابی لایه‌های شبکه یا بدافزار. |
| `netsh int ip reset` | بازگرداندن پشتهٔ IP و TCP به تنظیمات پیش‌فرض. | رفع مشکلات عمیق پیکربندی IP (معمولاً همراه با ریست Winsock استفاده می‌شود). |
| `netsh advfirewall show allprofiles` | نمایش تنظیمات فایروال برای همهٔ پروفایل‌ها (Domain، Private، Public). | کمک به تشخیص اینکه آیا قانونی از فایروال یک سرویس را مسدود کرده است. |
| `netsh wlan show profiles` | فهرست تمام شبکه‌های Wi-Fi ذخیره‌شده روی سیستم. | مفید برای مدیریت اتصالات بی‌سیم ذخیره‌شده یا خروجی‌گیری از آن‌ها. |
| `netsh wlan export profile name="WiFiName"` | خروجی‌گیری از یک پروفایل Wi-Fi به‌صورت فایل XML. | مناسب برای پشتیبان‌گیری، مستندسازی یا استقرار روی سیستم‌های دیگر. |
