# SIEM (Security Information and Event Management)

## مقدمه

**SIEM** مخفف **Security Information and Event Management** است و از ترکیب دو مفهوم تشکیل شده:
- **SIM (Security Information Management):** جمع‌آوری و ذخیره‌سازی لاگ
- **SEM (Security Event Management):** تحلیل و همبستگی (Correlation) رویدادها به‌صورت بلادرنگ

**هدف SIEM:**
- تجمیع لاگ‌ها از منابع متنوع
- تحلیل، همبسته‌سازی و تولید هشدار
- ایجاد دیدِ یکپارچه در سطح کل زیرساخت
- پشتیبانی از انطباق (Compliance) و فارنزیک

**SIEM مغز و چشمان مرکز عملیات امنیت (SOC) است:** به شناسایی تهدیداتی مانند سوءاستفادهٔ داخلی، نفوذ خارجی و نقض مقررات کمک می‌کند.

**مثال:** SIEM لاگ‌هایی از یک فایروال، یک سرور ویندوزی و یک آنتی‌ویروس دریافت می‌کند و این موارد را تشخیص می‌دهد:
- چندین تلاش ناموفق ورود از یک IP یکسان
- شناسایی یک اسکریپت مشکوک توسط آنتی‌ویروس

→ SIEM این رویدادها را همبسته می‌کند و هشداری برای احتمال حملهٔ Brute-Force یا حرکت جانبی (Lateral Movement) صادر می‌کند.

---

## مؤلفه‌های کلیدی یک سیستم SIEM

| مؤلفه | توضیح |
|---|---|
| **Log Collection** | جمع‌آوری لاگ از دستگاه‌ها (فایروال، سرور، Endpoint) با استفاده از Agent، Syslog، API یا SNMP |
| **Normalization** | تبدیل لاگ‌های با فرمت‌های مختلف به یک ساختار استاندارد برای تحلیل یکپارچه |
| **Correlation Engine** | شناسایی الگوها و ارتباط بین رویدادها در سیستم‌های مختلف برای کشف تهدید |
| **Alerting** | ارسال هشدار هنگام شناسایی الگوهای مشکوک یا از‌پیش‌تعریف‌شده، از طریق داشبورد، ایمیل یا یکپارچگی با سیستم Ticketing |
| **Dashboards & Reports** | رابط بصری برای مانیتورینگ فعالیت سیستم و تولید گزارش‌های انطباق/ممیزی |
| **Log Storage** | نگهداری لاگ‌ها برای ماه‌ها یا سال‌ها بر اساس الزامات انطباق (مانند PCI-DSS، GDPR) |

**مثال:** یک سرور ویندوزی چندین تلاش ناموفق ورود ثبت می‌کند. کمی بعد یک فایروال همان IP را مسدود می‌کند. SIEM این دو رویداد را همبسته می‌کند، آن IP را به‌عنوان مشکوک شناسایی و به تیم امنیت هشدار می‌دهد.

## مفهوم False Positive و True Positive

در تحلیل هشدارهای SIEM، هر رویداد شناسایی‌شده باید بررسی و برچسب‌گذاری شود:

- **FP (False Positive/Negative):** هشداری که به اشتباه صادر شده و در بررسی مشخص می‌شود تهدید واقعی نبوده است.
- **TP (True Positive/Negative):** هشداری که در بررسی تأیید می‌شود واقعاً یک رویداد امنیتی واقعی بوده است.

روند بررسی به این ترتیب است:

```
FP: False Positive/Negative → Alert was Generated → Investigate → TP
TP: True Positive/Negative
```

یعنی: هر هشدار (Alert) پس از صدور، باید توسط تحلیل‌گر SOC بررسی (Investigate) شود تا مشخص گردد آیا واقعاً یک تهدید واقعی (True Positive) بوده یا صرفاً یک هشدار کاذب (False Positive) است.

> **نکتهٔ آزمون:** میزان بالای False Positive یکی از بزرگ‌ترین چالش‌های عملیاتی تیم‌های SOC است؛ حجم زیاد هشدارهای کاذب می‌تواند باعث «خستگی از هشدار» (Alert Fatigue) شود و ریسک نادیده گرفتن یک True Positive واقعی را افزایش دهد.

## چرا سازمان‌ها به SIEM نیاز دارند؟

| دلیل | توضیح |
|---|---|
| **Improved Visibility** | تمرکز تمام رویدادهای امنیتی از دستگاه‌های شبکه، سیستم‌عامل‌ها و برنامه‌ها در یک نقطه |
| **Advanced Threat Detection** | شناسایی حملات پیچیده مانند APT از طریق همبسته‌سازی و تشخیص ناهنجاری |
| **Real-time Monitoring** | مانیتورینگ و هشداردهی آنی روی فعالیت‌های مشکوک |
| **Regulatory Compliance** | کمک به انطباق با استانداردهایی مانند GDPR، HIPAA و ISO 27001 از طریق لاگ‌گیری و گزارش‌دهی صحیح |
| **Faster Incident Response** | کاهش زمان پاسخ به حادثه و امکان اقدام پیشگیرانه از طریق هشدارهای SIEM |
| **Operational Efficiency** | کاهش نیاز به بررسی دستی لاگ‌ها با خودکارسازی تحلیل داده |

**مثال:** فرض کنید یک ادمین تازه‌کار به‌اشتباه دسترسی Root روی یک دیتابیس Production به خودش می‌دهد. بدون SIEM، این تغییر احتمالاً بدون توجه باقی می‌ماند. با SIEM، این تغییر دسترسی بلافاصله ثبت و برای بازبینی هشدار داده می‌شود.

## گردش‌کار (Workflow) SIEM

1. **Log Collection:** جمع‌آوری داده از فایروال‌ها، سرورها، سیستم‌عامل، برنامه‌ها و موارد دیگر.
2. **Normalization:** تبدیل فرمت‌های مختلف لاگ به یک ساختار یکپارچه.
3. **Storage:** ذخیرهٔ امن لاگ‌ها برای تحلیل بلادرنگ و تاریخی.
4. **Correlation:** تحلیل روابط بین رویدادها با استفاده از قوانین یا یادگیری ماشین.
5. **Detection & Alerting:** شناسایی رفتار مشکوک یا غیرعادی و صدور هشدار.
6. **Analysis & Response:** بررسی حادثه توسط تحلیل‌گران SOC و پاسخ متناسب.

> **جملهٔ کلیدی این بخش:** «SIEM فقط لاگ جمع نمی‌کند — آن‌ها را می‌فهمد.» (SIEM doesn't just collect logs – it understands them.)

## موارد کاربرد کلیدی SIEM در امنیت سایبری

| مورد کاربرد | توضیح |
|---|---|
| **Intrusion Detection** | شناسایی الگوهای رایج حمله مانند Port Scan، تلاش Brute-Force یا سوءاستفاده از سطح دسترسی |
| **Incident Response** | صدور هشدار و کمک به تیم امنیت برای پاسخ سریع و کارآمد |
| **User Behavior Monitoring (UEBA)** | یادگیری رفتار پایه (Baseline) کاربران و شناسایی ناهنجاری‌ها (مانند زمان یا مکان ورود غیرمعمول) |
| **Forensics** | ردیابی اینکه چه کسی، چه زمانی، کجا و چگونه در یک حادثهٔ امنیتی دخیل بوده، برای تحلیل پس از نفوذ |
| **Compliance Reporting** | کمک به سازمان‌ها برای برآورده‌کردن الزامات مقرراتی مانند GDPR، ISO 27001 یا HIPAA |

## ابزارهای محبوب SIEM در بازار

از میان ابزارهای شناخته‌شدهٔ SIEM می‌توان به موارد زیر اشاره کرد:

| ابزار | نکته |
|---|---|
| Splunk | یکی از پرکاربردترین پلتفرم‌های تحلیل لاگ و SIEM در سطح سازمانی |
| IBM QRadar / IBM Security QRadar | راهکار SIEM سازمانی با قابلیت مشاهدهٔ بلادرنگ زیرساخت IT |
| Microsoft Sentinel | SIEM ابری مایکروسافت، مبتنی بر Azure |
| LogRhythm | پلتفرم SIEM با تمرکز بر تشخیص و پاسخ سریع |
| Graylog | ابزار متن‌باز جمع‌آوری و تحلیل لاگ در سطح سازمانی |
| Exabeam | راهکار SIEM با تمرکز ویژه بر تحلیل رفتار کاربر (UEBA) |
| Datadog | پلتفرم مانیتورینگ که قابلیت‌های امنیتی و SIEM را نیز ارائه می‌دهد |
| Securonix | راهکار SIEM مبتنی بر ابر با تمرکز بر تحلیل رفتاری |

## جمع‌بندی نهایی

| مفهوم | نکتهٔ کلیدی |
|---|---|
| SIEM | ترکیب SIM (جمع‌آوری/ذخیرهٔ لاگ) + SEM (تحلیل/همبستگی بلادرنگ) |
| مؤلفه‌های اصلی | Log Collection، Normalization، Correlation Engine، Alerting، Dashboards & Reports، Log Storage |
| FP / TP | False Positive (هشدار کاذب) در برابر True Positive (تهدید واقعی تأییدشده) |
| گردش‌کار | Collection → Normalization → Storage → Correlation → Detection & Alerting → Analysis & Response |
| کاربرد اصلی | Intrusion Detection، Incident Response، UEBA، Forensics، Compliance Reporting |
| نقش در سازمان | مغز و چشمان SOC؛ کاهش زمان تشخیص و پاسخ به حادثه |
