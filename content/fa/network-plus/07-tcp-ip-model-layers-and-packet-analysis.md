# مدل TCP/IP؛ بررسی چهار لایه، پروتکل‌ها و تحلیل بسته‌ها در Wireshark

مدل **TCP/IP** چارچوب اصلی ارتباطات در اینترنت و بیشتر شبکه‌های امروزی است. این مدل توضیح می‌دهد داده چگونه از یک برنامه در دستگاه مبدأ خارج می‌شود، از شبکه عبور می‌کند و در دستگاه مقصد به برنامه مناسب تحویل داده می‌شود.

برخلاف مدل هفت‌لایه‌ای OSI که بیشتر جنبه آموزشی و مرجع دارد، TCP/IP مستقیماً بر پایه پروتکل‌هایی شکل گرفته است که در شبکه‌های واقعی استفاده می‌شوند. در رایج‌ترین تقسیم‌بندی، این مدل چهار لایه دارد:

1. Application
2. Transport
3. Internet
4. Network Access یا Network Interface

> در بعضی منابع، لایه Network Access به دو لایه Data Link و Physical تقسیم می‌شود و TCP/IP به‌صورت یک مدل پنج‌لایه نمایش داده می‌شود. هر دو شیوه رایج‌اند، اما مدل کلاسیک TCP/IP معمولاً چهارلایه‌ای است.

## هدف اصلی مدل TCP/IP

مدل TCP/IP برای استانداردسازی ارتباط میان سیستم‌های متفاوت طراحی شده است. مهم‌ترین اهداف آن عبارت‌اند از:

- فراهم‌کردن ارتباط میان شبکه‌های مختلف
- مشخص‌کردن روش آدرس‌دهی و مسیریابی داده
- انتقال داده میان برنامه‌های مبدأ و مقصد
- مستقل‌کردن ارتباطات شبکه از نوع سخت‌افزار و سیستم‌عامل
- فراهم‌کردن امکان توسعه و جایگزینی پروتکل‌ها در هر لایه

هر لایه وظیفه مشخصی دارد و خدمات خود را در اختیار لایه بالاتر قرار می‌دهد. در زمان ارسال، داده از لایه‌های بالا به پایین حرکت می‌کند و هر لایه اطلاعات کنترلی خود را به آن اضافه می‌کند. این فرایند **Encapsulation** نام دارد.

در مقصد، همین مسیر به‌صورت معکوس انجام می‌شود و اطلاعات افزوده‌شده توسط لایه‌ها حذف می‌شوند. این فرایند **Decapsulation** نام دارد.

## مقایسه مدل TCP/IP و OSI

مدل OSI شامل هفت لایه است، درحالی‌که مدل TCP/IP در شکل رایج چهار لایه دارد. نگاشت تقریبی این دو مدل به شکل زیر است:

| مدل OSI | مدل TCP/IP |
|---|---|
| Application | Application |
| Presentation | Application |
| Session | Application |
| Transport | Transport |
| Network | Internet |
| Data Link | Network Access |
| Physical | Network Access |

در مدل TCP/IP، وظایف سه لایه Application، Presentation و Session مدل OSI معمولاً در یک لایه به نام Application ترکیب شده‌اند. همچنین دو لایه Data Link و Physical در لایه Network Access قرار می‌گیرند.

> این نگاشت کاملاً یک‌به‌یک و مطلق نیست. TCP/IP و OSI مستقل از یکدیگر طراحی شده‌اند و هدف از این جدول، مقایسه آموزشی وظایف آن‌هاست.

## واحد داده در هر لایه

هنگام عبور داده از لایه‌های TCP/IP، نام واحد داده تغییر می‌کند:

| لایه | واحد داده متداول |
|---|---|
| Application | Data یا Message |
| Transport | Segment در TCP و Datagram در UDP |
| Internet | Packet یا IP Datagram |
| Network Access | Frame |
| محیط انتقال | Bits |

برای نمونه، یک درخواست HTTP ابتدا در لایه Application به شکل داده ایجاد می‌شود. TCP آن را داخل Segment قرار می‌دهد، IP برای آن Packet می‌سازد و Ethernet آن را درون Frame قرار می‌دهد.

# لایه Application

لایه **Application** بالاترین لایه مدل TCP/IP است و خدمات شبکه را مستقیماً در اختیار برنامه‌های کاربر قرار می‌دهد. مرورگر وب، برنامه ایمیل، ابزار انتقال فایل و نرم‌افزارهای مدیریت شبکه از پروتکل‌های این لایه استفاده می‌کنند.

این لایه صرفاً خود نرم‌افزار نیست؛ بلکه پروتکل‌ها و قواعدی است که نرم‌افزار برای ارتباط شبکه‌ای از آن‌ها استفاده می‌کند.

## وظایف لایه Application

- فراهم‌کردن خدمات شبکه برای برنامه‌ها
- تعریف قالب و معنای پیام‌های کاربردی
- مدیریت درخواست و پاسخ میان Client و Server
- شناسایی منابع و سرویس‌های شبکه
- انجام بخشی از وظایف مرتبط با Session و Presentation
- تبدیل داده برنامه به قالب قابل انتقال در شبکه

## پروتکل‌های مهم لایه Application

### HTTP و HTTPS

پروتکل **HTTP** برای انتقال صفحات وب، APIها و منابع وب استفاده می‌شود. **HTTPS** همان HTTP روی یک کانال رمزنگاری‌شده TLS است.

پورت‌های متداول:

- HTTP: پورت TCP 80
- HTTPS: پورت TCP 443

> HTTPS یک پروتکل کاملاً جدا از HTTP نیست؛ در عمل HTTP است که داخل اتصال امن TLS منتقل می‌شود.

### DNS

پروتکل **DNS** نام دامنه را به IP و در برخی موارد IP را به نام تبدیل می‌کند. بیشتر درخواست‌های عادی DNS از UDP پورت 53 استفاده می‌کنند، اما TCP نیز برای پاسخ‌های بزرگ، Zone Transfer و برخی سناریوهای دیگر استفاده می‌شود.

### DHCP

پروتکل **DHCP** تنظیمات شبکه مانند IP، Subnet Mask، Default Gateway و DNS Server را به‌صورت خودکار در اختیار Client قرار می‌دهد.

پورت‌های اصلی:

- UDP 67 برای Server
- UDP 68 برای Client

### FTP و TFTP

**FTP** برای انتقال فایل استفاده می‌شود و دارای کانال کنترل و داده است. FTP به‌صورت پیش‌فرض رمزنگاری ندارد.

**TFTP** پروتکل سبک‌تری است که بر پایه UDP کار می‌کند و معمولاً در راه‌اندازی تجهیزات، انتقال فایل‌های کوچک و PXE Boot کاربرد دارد.

### SMTP، POP3 و IMAP

- **SMTP** برای ارسال ایمیل میان Client و Server یا میان Mail Serverها استفاده می‌شود.
- **POP3** معمولاً پیام‌ها را از Server دریافت می‌کند و مدل ساده‌تری دارد.
- **IMAP** پیام‌ها و پوشه‌ها را روی Server نگه می‌دارد و میان چند دستگاه همگام می‌کند.

### SSH و Telnet

- **SSH** دسترسی امن و رمزنگاری‌شده به خط فرمان سیستم راه دور را فراهم می‌کند.
- **Telnet** عملکرد مشابهی دارد، اما داده‌ها را به‌صورت متن واضح منتقل می‌کند و برای محیط‌های ناامن مناسب نیست.

### SNMP

پروتکل **SNMP** برای پایش و مدیریت تجهیزات شبکه استفاده می‌شود. مدیر شبکه می‌تواند اطلاعاتی مانند وضعیت Interface، مصرف پهنای باند و خطاها را از طریق اشیای تعریف‌شده در MIB دریافت کند.

# لایه Transport

لایه **Transport** ارتباط انتهابه‌انتها میان برنامه‌های دو دستگاه را مدیریت می‌کند. این لایه مشخص می‌کند داده مربوط به کدام برنامه است و با استفاده از شماره پورت، آن را به فرایند مناسب تحویل می‌دهد.

پروتکل‌های اصلی این لایه TCP و UDP هستند.

## وظایف لایه Transport

- تقسیم داده بزرگ به بخش‌های کوچک‌تر
- بازسازی داده در مقصد
- شناسایی برنامه مبدأ و مقصد با شماره پورت
- Multiplexing چند ارتباط روی یک IP
- کنترل جریان در TCP
- تشخیص گم‌شدن و ارسال مجدد داده در TCP
- مرتب‌سازی Segmentها در TCP
- بررسی خطا با Checksum

## مفهوم شماره پورت

IP دستگاه را در شبکه مشخص می‌کند، اما شماره پورت برنامه یا سرویس را روی آن دستگاه مشخص می‌کند.

برای مثال، ممکن است یک Server دارای یک IP باشد اما هم‌زمان خدمات زیر را ارائه دهد:

- وب روی پورت 80 و 443
- SSH روی پورت 22
- DNS روی پورت 53
- ایمیل روی پورت 25 یا 587

هر ارتباط معمولاً با ترکیب زیر شناسایی می‌شود:

```text
Source IP + Source Port + Destination IP + Destination Port + Protocol
```

این ترکیب را معمولاً **Five-Tuple** می‌نامند.

## TCP

پروتکل **Transmission Control Protocol** اتصال‌گرا و قابل‌اعتماد است. TCP پیش از تبادل عادی داده، یک اتصال منطقی میان دو طرف ایجاد می‌کند.

ویژگی‌های مهم TCP:

- Connection-Oriented
- تحویل قابل‌اعتماد داده
- شماره‌گذاری Segmentها
- مرتب‌سازی داده در مقصد
- ارسال Acknowledgment
- ارسال مجدد داده‌های ازدست‌رفته
- کنترل جریان
- کنترل ازدحام
- تشخیص خطا با Checksum

### Three-Way Handshake

برقراری اتصال TCP معمولاً با سه مرحله انجام می‌شود:

1. Client یک Segment با Flag برابر SYN ارسال می‌کند.
2. Server با SYN-ACK پاسخ می‌دهد.
3. Client یک ACK ارسال می‌کند.

```text
Client                         Server
  | -------- SYN ----------->   |
  | <------ SYN, ACK --------   |
  | -------- ACK ----------->   |
```

پس از این مراحل، اتصال آماده انتقال داده است.

### Sequence Number و Acknowledgment Number

TCP برای کنترل ترتیب و اطمینان از دریافت داده از دو مقدار اصلی استفاده می‌کند:

- **Sequence Number:** شماره موقعیت داده ارسال‌شده در جریان بایت‌ها
- **Acknowledgment Number:** شماره بایت بعدی که گیرنده انتظار دارد

برای مثال، اگر گیرنده ACK برابر 1501 ارسال کند، یعنی همه بایت‌ها تا شماره 1500 را دریافت کرده و منتظر بایت 1501 است.

### Windowing و Flow Control

گیرنده TCP با مقدار **Window Size** اعلام می‌کند چه مقدار داده را بدون دریافت ACK جدید می‌تواند بپذیرد. این مکانیزم مانع از آن می‌شود که فرستنده با سرعتی بیشتر از ظرفیت گیرنده داده ارسال کند.

در TCP جدید، Window Scaling می‌تواند اندازه مؤثر پنجره را از محدودیت 65535 بایت فراتر ببرد.

### Reliability در TCP

قابل‌اعتمادبودن TCP به معنی تضمین مطلق تحویل در هر شرایطی نیست. TCP تلاش می‌کند با روش‌هایی مانند ACK، Timeout و Retransmission تحویل صحیح و مرتب داده را فراهم کند. اگر ارتباط شبکه به‌طور کامل قطع شود، TCP نیز نمی‌تواند داده را تحویل دهد و در نهایت خطا گزارش می‌شود.

## UDP

پروتکل **User Datagram Protocol** بدون اتصال و سبک است. UDP پیش از ارسال داده Handshake انجام نمی‌دهد و تحویل، ترتیب یا ارسال مجدد داده را تضمین نمی‌کند.

ویژگی‌های اصلی UDP:

- Connectionless
- Header کوچک‌تر از TCP
- تأخیر کمتر
- بدون ACK در سطح UDP
- بدون Retransmission داخلی
- بدون تضمین ترتیب بسته‌ها
- مناسب برای کاربردهای بلادرنگ و درخواست‌های کوتاه

کاربردهای رایج UDP:

- DNS
- DHCP
- VoIP
- تماس ویدئویی
- بازی‌های آنلاین
- پخش زنده
- NTP
- TFTP

> استفاده از UDP لزوماً به معنای غیرقابل‌اعتمادبودن کل برنامه نیست. بعضی پروتکل‌های کاربردی، قابلیت اطمینان را خودشان روی UDP پیاده‌سازی می‌کنند. QUIC نمونه مهمی است که روی UDP کار می‌کند اما تحویل قابل‌اعتماد، رمزنگاری و کنترل ازدحام را در سطح خود فراهم می‌کند.

## مقایسه TCP و UDP

| ویژگی | TCP | UDP |
|---|---|---|
| نوع ارتباط | اتصال‌گرا | بدون اتصال |
| قابلیت اطمینان | دارد | در خود UDP ندارد |
| حفظ ترتیب | دارد | ندارد |
| ارسال مجدد | دارد | ندارد |
| کنترل جریان | دارد | ندارد |
| سربار Header | بیشتر | کمتر |
| تأخیر اولیه | بیشتر | کمتر |
| کاربرد معمول | وب، SSH، ایمیل، انتقال فایل | DNS، VoIP، Streaming، بازی |

# لایه Internet

لایه **Internet** مسئول آدرس‌دهی منطقی و انتقال Packet میان شبکه‌های مختلف است. Routerها عمدتاً در این لایه تصمیم می‌گیرند Packet از چه مسیری به مقصد برسد.

## وظایف لایه Internet

- تعریف آدرس IP مبدأ و مقصد
- مسیریابی Packet میان شبکه‌ها
- انتخاب Next Hop
- جلوگیری از گردش بی‌نهایت Packet با TTL یا Hop Limit
- Fragmentation در شرایط خاص IPv4
- گزارش برخی خطاها و وضعیت‌های شبکه با ICMP

## پروتکل IP

پروتکل **IP** پایه اصلی لایه Internet است. دو نسخه رایج آن عبارت‌اند از:

- IPv4
- IPv6

IP یک پروتکل Best-Effort است؛ یعنی به‌تنهایی تحویل Packet، حفظ ترتیب یا جلوگیری از تکرار را تضمین نمی‌کند. این مسئولیت‌ها در صورت نیاز توسط لایه‌های بالاتر انجام می‌شوند.

## IPv4

IPv4 از آدرس 32 بیتی استفاده می‌کند، مانند:

```text
192.168.1.10
```

برخی فیلدهای مهم Header در IPv4:

- Version
- Header Length
- Total Length
- Identification
- Flags
- Fragment Offset
- TTL
- Protocol
- Header Checksum
- Source Address
- Destination Address

### TTL

فیلد **Time To Live** با عبور از هر Router حداقل یک واحد کاهش می‌یابد. اگر TTL به صفر برسد، Router بسته را حذف می‌کند و معمولاً پیام ICMP Time Exceeded می‌فرستد. هدف اصلی جلوگیری از Loop بی‌نهایت در مسیریابی است.

### فیلد Protocol

این فیلد مشخص می‌کند Payload بسته IP متعلق به کدام پروتکل لایه بالاتر است. برای نمونه:

- ICMP: مقدار 1
- TCP: مقدار 6
- UDP: مقدار 17

## IPv6

IPv6 از آدرس‌های 128 بیتی استفاده می‌کند و برای حل محدودیت فضای آدرس IPv4 طراحی شده است.

نمونه آدرس IPv6:

```text
2001:db8:10::25
```

در IPv6، فیلد **Hop Limit** نقشی مشابه TTL در IPv4 دارد.

## ICMP

پروتکل **Internet Control Message Protocol** برای گزارش خطا و پیام‌های کنترلی شبکه استفاده می‌شود. دستور `ping` معمولاً از ICMP Echo Request و Echo Reply استفاده می‌کند.

نمونه کاربردهای ICMP:

- بررسی دسترسی‌پذیری مقصد
- اعلام Destination Unreachable
- اعلام Time Exceeded
- کمک به Path MTU Discovery

> ICMP صرفاً یک ابزار Ping نیست و بخش مهمی از عملکرد صحیح IP را تشکیل می‌دهد. مسدودکردن کامل ICMP می‌تواند برخی قابلیت‌های شبکه را مختل کند.

## پروتکل‌های مسیریابی

پروتکل‌های مسیریابی مانند OSPF و BGP اطلاعات مسیر را میان Routerها مبادله می‌کنند. خود Packetهای این پروتکل‌ها ممکن است مستقیماً روی IP یا روی TCP منتقل شوند، اما کارکرد آن‌ها به تصمیم‌گیری مسیریابی مربوط است.

- **OSPF:** پروتکل مسیریابی داخلی Link-State
- **BGP:** پروتکل اصلی مسیریابی میان Autonomous Systemهای اینترنت

> BGP برای انتقال پیام‌های خود از TCP پورت 179 استفاده می‌کند. بنابراین از نظر انتقال، روی TCP قرار دارد؛ اما از نظر نقش و هدف، پروتکل مسیریابی محسوب می‌شود.

# لایه Network Access یا Network Interface

لایه **Network Access** پایین‌ترین لایه مدل چهارلایه‌ای TCP/IP است. این لایه نحوه انتقال Packet روی شبکه محلی یا لینک فیزیکی را مشخص می‌کند.

در نگاشت به OSI، وظایف لایه‌های Data Link و Physical در این بخش قرار می‌گیرند.

## وظایف لایه Network Access

- ساخت Frame
- استفاده از آدرس MAC در شبکه محلی
- تعیین روش دسترسی به رسانه
- تشخیص برخی خطاهای Frame
- انتقال بیت‌ها روی کابل، فیبر یا امواج رادیویی
- تعامل با کارت شبکه و Driver
- تحویل Frame به دستگاه بعدی روی لینک محلی

## Ethernet

**Ethernet** فناوری غالب شبکه‌های LAN سیمی است. یک Ethernet Frame معمولاً شامل این بخش‌هاست:

- Destination MAC
- Source MAC
- EtherType یا Length
- Payload
- Frame Check Sequence

فیلد EtherType نوع داده داخل Frame را مشخص می‌کند. برای نمونه:

- IPv4: مقدار `0x0800`
- ARP: مقدار `0x0806`
- IPv6: مقدار `0x86DD`

## آدرس MAC

MAC Address یک شناسه لایه لینک است که برای تحویل Frame در شبکه محلی استفاده می‌شود. نمونه:

```text
00:1A:2B:3C:4D:5E
```

هنگامی که Packet از Router عبور می‌کند، آدرس‌های IP مبدأ و مقصد معمولاً ثابت می‌مانند، اما MAC Addressهای Frame برای هر لینک تغییر می‌کنند.

برای مثال، هنگام ارسال داده به اینترنت:

- Destination IP برابر IP Server اینترنتی است.
- Destination MAC در شبکه محلی برابر MAC مربوط به Default Gateway است.

## ARP

پروتکل **Address Resolution Protocol** برای یافتن MAC متناظر با یک IPv4 در شبکه محلی استفاده می‌شود.

فرایند ساده ARP:

1. دستگاه بررسی می‌کند آیا MAC مقصد در ARP Cache وجود دارد.
2. اگر وجود نداشته باشد، یک ARP Request به‌صورت Broadcast ارسال می‌کند.
3. دستگاه دارای آن IP با ARP Reply پاسخ می‌دهد.
4. نگاشت IP به MAC برای مدتی در ARP Cache ذخیره می‌شود.

نمونه پیام مفهومی:

```text
Who has 192.168.1.1? Tell 192.168.1.20
```

> جایگاه دقیق ARP در مدل‌های لایه‌ای محل اختلاف آموزشی است. ARP میان وظایف لایه 2 و 3 قرار می‌گیرد، اما معمولاً در مدل TCP/IP در لایه Network Access بررسی می‌شود.

## Wi-Fi

شبکه‌های Wi-Fi بر خانواده استانداردهای IEEE 802.11 استوارند. Wi-Fi نیز وظایف لایه لینک و فیزیکی را انجام می‌دهد، اما ساختار Frame و روش دسترسی آن با Ethernet تفاوت دارد.

## PPP

پروتکل **Point-to-Point Protocol** برای ارتباطات نقطه‌به‌نقطه استفاده می‌شود و قابلیت‌هایی مانند Encapsulation، تشخیص خطا و مذاکره پارامترهای لینک را فراهم می‌کند.

# فرایند Encapsulation از برنامه تا شبکه

فرض کنید کاربر آدرس یک وب‌سایت HTTPS را در مرورگر وارد می‌کند. روند کلی انتقال می‌تواند چنین باشد:

1. مرورگر در لایه Application یک درخواست HTTP ایجاد می‌کند.
2. در HTTPS، داده HTTP توسط TLS رمزنگاری می‌شود.
3. TCP داده را Segment می‌کند و Source Port و Destination Port را اضافه می‌کند.
4. IP آدرس‌های مبدأ و مقصد را در Header قرار می‌دهد.
5. Ethernet آدرس‌های MAC لینک محلی را اضافه می‌کند.
6. Frame به بیت تبدیل و روی رسانه ارسال می‌شود.

ساختار تو در تو را می‌توان به‌صورت زیر نمایش داد:

```text
Ethernet Frame
└── IP Packet
    └── TCP Segment
        └── TLS Record
            └── HTTP Data
```

در مقصد، هر لایه Header مربوط به خود را بررسی و حذف می‌کند تا در نهایت داده به برنامه مقصد برسد.

# تحلیل عملی بسته‌ها در Wireshark

**Wireshark** ابزاری برای Capture و تحلیل ترافیک شبکه است. این ابزار داده را در چند سطح نمایش می‌دهد و به‌خوبی ساختار لایه‌ای شبکه را نشان می‌دهد.

پنجره اصلی Wireshark معمولاً سه بخش دارد:

1. Packet List: فهرست Packetهای Captureشده
2. Packet Details: نمایش ساختار لایه‌ای Packet انتخاب‌شده
3. Packet Bytes: نمایش داده خام به‌صورت Hex و ASCII

## ستون‌های متداول Packet List

- No: شماره Packet در Capture
- Time: زمان ثبت Packet
- Source: آدرس مبدأ
- Destination: آدرس مقصد
- Protocol: پروتکل تشخیص‌داده‌شده
- Length: طول Packet یا Frame
- Info: خلاصه اطلاعات پروتکل

## بررسی یک Frame در Wireshark

در بخش Packet Details معمولاً ساختاری مشابه زیر مشاهده می‌شود:

```text
Frame
Ethernet II
Internet Protocol Version 4
Transmission Control Protocol
Application Data
```

این نمایش دقیقاً Encapsulation را نشان می‌دهد. هر بخش، Header یکی از لایه‌ها را باز می‌کند.

## تحلیل Ethernet Header

با بازکردن بخش Ethernet II می‌توان موارد زیر را دید:

- Source MAC Address
- Destination MAC Address
- EtherType

اگر Packet به مقصدی خارج از شبکه محلی ارسال شود، Destination MAC معمولاً متعلق به Router یا Default Gateway است، نه Server نهایی اینترنت.

## تحلیل IP Header

در بخش IPv4 می‌توان اطلاعات زیر را مشاهده کرد:

- Source IP
- Destination IP
- TTL
- Header Length
- Total Length
- Protocol
- Identification
- Flags و Fragment Offset
- Header Checksum

فیلد Protocol مشخص می‌کند داده داخل IP متعلق به TCP، UDP یا پروتکل دیگری است.

## تحلیل TCP Header

در بخش TCP اطلاعات زیر دیده می‌شود:

- Source Port
- Destination Port
- Sequence Number
- Acknowledgment Number
- Header Length
- Flags
- Window Size
- Checksum
- TCP Options

Flagهای مهم TCP:

| Flag | کاربرد |
|---|---|
| SYN | آغاز اتصال و همگام‌سازی Sequence Number |
| ACK | معتبر بودن Acknowledgment Number |
| FIN | پایان عادی اتصال |
| RST | قطع یا رد فوری اتصال |
| PSH | درخواست تحویل سریع‌تر داده به برنامه |
| URG | وجود داده فوری؛ امروزه کاربرد محدودی دارد |

## دنبال‌کردن یک ارتباط TCP

برای مشاهده کامل جریان یک ارتباط می‌توان روی Packet راست‌کلیک کرد و از گزینه زیر استفاده کرد:

```text
Follow > TCP Stream
```

Wireshark در این حالت داده‌های دو جهت ارتباط را کنار هم بازسازی می‌کند. در ارتباط HTTPS معمولاً محتوای Application رمزنگاری‌شده است و بدون کلید مناسب قابل خواندن نیست.

## Display Filterهای کاربردی

```text
# فقط ترافیک TCP
tcp

# فقط ترافیک UDP
udp

# فقط ترافیک IPv4
ip

# ترافیک یک IP خاص
ip.addr == 192.168.1.10

# بسته‌های ارسالی از یک IP
ip.src == 192.168.1.10

# بسته‌های دریافتی به یک IP
ip.dst == 192.168.1.10

# ترافیک یک پورت TCP
tcp.port == 443

# فقط بسته‌های SYN اولیه
TCP.flags.syn == 1 && tcp.flags.ack == 0

# ARP
arp

# DNS
dns

# ICMP
icmp
```

> نام صحیح فیلتر Wireshark برای Flag به حروف کوچک نوشته می‌شود: `tcp.flags.syn`. در مثال بالا نیز باید `tcp.flags.syn` باشد؛ Display Filterها نسبت به نام فیلد حساس‌اند.

فرم صحیح:

```text
tcp.flags.syn == 1 && tcp.flags.ack == 0
```

## تفاوت Capture Filter و Display Filter

Wireshark دو نوع فیلتر دارد:

- **Capture Filter:** پیش از Capture تعیین می‌کند چه Packetهایی ثبت شوند.
- **Display Filter:** پس از Capture تعیین می‌کند چه Packetهایی نمایش داده شوند.

مثال Capture Filter:

```text
host 192.168.1.10
port 53
tcp port 443
```

مثال Display Filter:

```text
ip.addr == 192.168.1.10
dns
tcp.port == 443
```

Syntax این دو نوع فیلتر با یکدیگر متفاوت است.

# مسیر یک Packet در شبکه

فرض کنید سیستم با IP `192.168.1.20` می‌خواهد به Server با IP `203.0.113.10` متصل شود.

سیستم ابتدا با Subnet Mask تشخیص می‌دهد مقصد در شبکه محلی نیست. بنابراین Packet را به Default Gateway می‌فرستد.

در Frame اول:

```text
Source MAC      = MAC سیستم
Destination MAC = MAC روتر
Source IP       = 192.168.1.20
Destination IP  = 203.0.113.10
```

Router Frame را حذف، IP Packet را بررسی و سپس برای لینک بعدی یک Frame جدید می‌سازد. به همین دلیل MAC Addressها در هر Hop تغییر می‌کنند، اما IPها در حالت عادی ثابت می‌مانند.

> در صورت وجود NAT، Source IP یا Destination IP نیز ممکن است در مسیر تغییر کند. بنابراین ثابت‌ماندن IPها مربوط به مسیریابی عادی بدون ترجمه آدرس است.

# تفاوت آدرس‌دهی در لایه‌ها

هر لایه برای نوع خاصی از شناسایی استفاده می‌شود:

| نوع آدرس | لایه | هدف |
|---|---|---|
| Domain Name | Application | نام قابل‌فهم سرویس |
| Port Number | Transport | شناسایی برنامه یا فرایند |
| IP Address | Internet | شناسایی Host و مسیریابی میان شبکه‌ها |
| MAC Address | Network Access | تحویل Frame در لینک محلی |

برای دسترسی به یک وب‌سایت ممکن است این زنجیره رخ دهد:

```text
example.com
    ↓ DNS
203.0.113.10
    ↓ Routing
Default Gateway MAC
    ↓ Ethernet/Wi-Fi
Bits on media
```

# نکات اصلاحی و دقیق‌تر

## TCP/IP همیشه دقیقاً چهار لایه نیست

در بیشتر منابع، TCP/IP چهار لایه دارد؛ اما بعضی کتاب‌ها برای آموزش بهتر، Network Access را به Data Link و Physical تقسیم کرده و مدل پنج‌لایه‌ای ارائه می‌کنند. این تفاوت به معنی وجود دو استاندارد ناسازگار نیست.

## Network Access فقط لایه فیزیکی نیست

این لایه هم انتقال فیزیکی بیت‌ها و هم ساخت و تحویل Frame را پوشش می‌دهد. بنابراین Ethernet، MAC Address و FCS نیز بخشی از آن هستند.

## IP تحویل قابل‌اعتماد را تضمین نمی‌کند

IP بسته‌ها را با مدل Best-Effort حمل می‌کند. بسته ممکن است گم، تکراری یا خارج از ترتیب دریافت شود. TCP در صورت نیاز این مشکلات را در لایه Transport مدیریت می‌کند.

## UDP الزاماً برای همه Streamingها استفاده نمی‌شود

بسیاری از سرویس‌های Streaming سنتی می‌توانند از TCP و HTTPS استفاده کنند. امروزه HTTP/3 از QUIC روی UDP استفاده می‌کند. انتخاب TCP یا UDP به طراحی پروتکل و نیاز برنامه بستگی دارد.

## Router بر اساس IP تصمیم می‌گیرد

Switch معمولاً Frame را با MAC Address در LAN هدایت می‌کند، درحالی‌که Router مسیر Packet را با Destination IP و Routing Table تعیین می‌کند.

## Wireshark همیشه تمام Frame را نمی‌بیند

بسته به کارت شبکه، Driver و Offloading، ممکن است FCS در Capture موجود نباشد یا Checksum به‌اشتباه نامعتبر نمایش داده شود. ویژگی‌هایی مانند TCP Checksum Offload باعث می‌شوند سیستم‌عامل Packet را پیش از محاسبه نهایی Checksum به Wireshark تحویل دهد.

# جمع‌بندی

مدل TCP/IP ارتباطات شبکه را به چهار بخش اصلی تقسیم می‌کند:

- **Application:** خدمات و پروتکل‌های مورد استفاده برنامه‌ها
- **Transport:** ارتباط میان فرایندها، Portها و انتقال TCP یا UDP
- **Internet:** آدرس‌دهی IP و مسیریابی Packetها
- **Network Access:** ساخت Frame و انتقال روی Ethernet، Wi-Fi یا دیگر لینک‌ها

در زمان ارسال، هر لایه Header خود را به داده اضافه می‌کند. در نتیجه یک پیام کاربردی به Segment، سپس Packet و در نهایت Frame تبدیل می‌شود. ابزار Wireshark این ساختار تو در تو را نمایش می‌دهد و امکان بررسی MAC، IP، Port، Flagهای TCP و داده خام را فراهم می‌کند.

درک مدل TCP/IP پایه تحلیل ترافیک، عیب‌یابی شبکه، پیکربندی Firewall، کار با Router و Switch و یادگیری مباحث پیشرفته‌تری مانند NAT، VPN، DNS، Routing و امنیت شبکه است.
