# احراز هویت و کنترل دسترسی

## ۱. احراز هویت (Authentication) و کنترل دسترسی (Access Control)

### Authentication چیست؟

Authentication فرآیند تأیید هویت یک کاربر یا دستگاه است — اطمینان از اینکه شخص یا سیستم، همان است که ادعا می‌کند. این کار از طریق روش‌های زیر انجام می‌شود:

1. رمز عبور (Password)
2. کارت‌های هوشمند (Smart cards)
3. داده‌های بیومتریک (مانند اثر انگشت)

**مثال:** ورود به یک سیستم با نام‌کاربری و رمز عبور.

### Access Control چیست؟

Access Control تعیین می‌کند کاربران پس از احراز هویت چه کارهایی می‌توانند انجام دهند. دسترسی به سیستم‌ها، فایل‌ها و توابع را بر اساس نقش‌ها یا مجوزها محدود می‌کند.

**مثال:** فقط تیم مالی می‌تواند صفحات گسترده بودجه را ویرایش کند.

### تفاوت Authentication و Authorization

| مفهوم | سؤالی که پاسخ می‌دهد | هدف |
|---|---|---|
| **Authentication** | «تو کی هستی؟» | تأیید هویت |
| **Authorization** | «مجاز به انجام چه کاری هستی؟» | اعطا یا محدودسازی مجوزها |

---

## ۲. مدیریت حساب‌های کاربری و امنیت رمز عبور (بخش اول)

### مدیریت حساب‌های کاربری

مدیران باید کنترل کنند چه کسانی به سیستم‌ها دسترسی دارند، نقش‌ها را تعریف کنند و حساب‌های بلااستفاده یا رهاشده را غیرفعال کنند.

### مدیریت رمز عبور

سیاست‌های رمز عبور باید اجرا شوند:
- حداقل طول (Minimum length)
- الزامات پیچیدگی (Complexity requirements)
- انقضای دوره‌ای (Periodic expiration)
- جلوگیری از استفادهٔ مجدد از رمزهای قدیمی (Prohibit reuse of old passwords)

### Single Sign-On (SSO)

امکان احراز هویت یک‌بار و دسترسی به چند سیستم را فراهم می‌کند. کاربرد بهبود پذیرش کاربر، اما در صورت نفوذ، مهاجم به تمام سیستم‌ها دسترسی پیدا می‌کند.

### Local Authentication

داده‌های احراز هویت به‌صورت محلی روی دستگاه ذخیره می‌شوند. مناسب سیستم‌های مستقل یا محدود.

---

## ۳. مدیریت حساب‌های کاربری و امنیت رمز عبور (بخش دوم)

### LDAP

پروتکلی برای دسترسی به اطلاعات کاربران در دایرکتوری‌هایی مانند Microsoft Active Directory. برای احراز هویت متمرکز استفاده می‌شود.

### Certificates (گواهینامه‌ها)

در زیرساخت کلید عمومی (PKI) برای تأیید هویت کاربر و امن‌سازی ارتباطات (SSL/TLS) به کار می‌روند.

### Multifactor Authentication (MFA)

نیازمند دو یا چند عامل احراز هویت است:
- **Something you know** (چیزی که می‌دانی) — رمز عبور، PIN
- **Something you have** (چیزی که داری) — توکن، کارت هوشمند
- **Something you are** (چیزی که هستی) — اثر انگشت، تشخیص چهره

MFA وضعیت امنیتی را به‌شکل چشمگیری بهبود می‌بخشد.

---

## ۴. روش‌های احراز هویت کاربران

### Public Key Infrastructure (PKI)

چارچوبی برای صدور و مدیریت گواهینامه‌های دیجیتال. کاربردها:
- امن‌سازی ترافیک وب (HTTPS)
- امضای دیجیتال
- ورود مبتنی بر گواهینامه (Certificate-based login)

### Kerberos

پروتکل احراز هویت مبتنی بر بلیت (Ticket-based) که در دامنه‌های ویندوز استفاده می‌شود:
- مرجع مرکزی: KDC (Key Distribution Center)
- اعتبارنامه‌ها هرگز به‌صورت متن ساده ارسال نمی‌شوند.

### AAA (Authentication, Authorization, Accounting)

مدل کنترل دسترسی سه‌لایه:
- **Authentication:** تأیید هویت
- **Authorization:** اعطای دسترسی مناسب
- **Accounting:** ثبت فعالیت‌ها

پروتکل‌های رایج با RADIUS یا TACACS+ استفاده می‌شود.

### Web Services

برنامه‌های مدرن از احراز هویت مبتنی بر API با پروتکل‌هایی مانند OAuth 2.0 و OpenID Connect استفاده می‌کنند.

### Unified Voice Services

احراز هویت برای سیستم‌های VoIP با مکانیزم‌های SIP-based.

### Network Controllers

احراز هویت متمرکز برای دستگاه‌های سیمی/بی‌سیم از طریق پلتفرم‌هایی مانند Cisco DNA Center.

---

## ۵. Network Access Control (NAC) و پروتکل‌های Challenge-Based

### NAC

چارچوبی امنیتی برای اجرای سیاست‌های دسترسی بر اساس کاربر، دستگاه، موقعیت یا وضعیت امنیتی (Security Posture). قابلیت‌ها:
- مسدودسازی دستگاه‌های آلوده یا غیرمنطبق
- ایزوله‌سازی کاربران مهمان (Guest user isolation)
- یکپارچگی با آنتی‌ویروس، فایروال و ابزارهای MDM
- ابزارهای محبوب: **Cisco ISE**، **Aruba ClearPass**

### IEEE 802.1X

استاندارد کنترل دسترسی شبکه مبتنی بر پورت:
- از EAP برای تبادل احراز هویت استفاده می‌کند.
- نقش‌ها:
  - **Supplicant:** دستگاه کاربر
  - **Authenticator:** سوییچ یا Access Point
  - **Authentication Server:** مثلاً RADIUS

### Challenge-Based Protocols

روش‌های احراز هویت مبتنی بر تبادل چالش-پاسخ (Challenge-Response):
- **CHAP** (Challenge Handshake Authentication Protocol)
- **EAP-CHAP / EAP-TLS**
- **MS-CHAPv2** (مورد استفاده در دامنه‌های ویندوز)
- امن‌تر از روش‌های صرفاً مبتنی بر رمز عبور.

### Posture Assessment

بررسی انطباق دستگاه پیش از اعطای دسترسی شبکه (وضعیت آنتی‌ویروس، نسخهٔ سیستم‌عامل، فایروال و ...). اغلب در سیستم‌های NAC تعبیه شده است.

## ۶. مدل‌های Authorization (RBAC، ABAC، DAC)

### RBAC – Role-Based Access Control

دسترسی بر اساس نقش کاربر در سازمان اعطا می‌شود.
- **مثال:** تمام اعضای تیم مالی به پوشهٔ حقوق و دستمزد دسترسی دارند.
- **مزایا:** مدیریت آسان، همسو با ساختار سازمانی
- **معایب:** انعطاف کمتر در سناریوهای پیچیده

### ABAC – Attribute-Based Access Control

دسترسی بر اساس ارزیابی ویژگی‌های مختلف تعیین می‌شود:
- ویژگی **کاربر** (مانند عنوان شغلی، بخش)
- ویژگی **منبع** (مانند طبقه‌بندی)
- ویژگی **محیط** (مانند ساعت دسترسی)
- **مزایا:** بسیار انعطاف‌پذیر و مقیاس‌پذیر
- **معایب:** پیاده‌سازی و نگهداری پیچیده

### DAC – Discretionary Access Control

مالک یک منبع تعیین می‌کند چه کسی می‌تواند به آن دسترسی داشته باشد.
- **مثال:** یک کاربر یک صفحهٔ گسترده را با همکارش به اشتراک می‌گذارد.
- **مزایا:** کنترل و انعطاف در سطح کاربر
- **معایب:** ریسک افشای تصادفی یا سوءاستفاده

---

## ۷. Identity Federation و Single Sign-On (SSO)

### Identity Federation

رابطه‌ای مبتنی بر اعتماد که به کاربران امکان می‌دهد با یک هویت دیجیتال به چند سیستم دسترسی داشته باشند. کاربر از طریق یک **Identity Provider (IdP)** وارد می‌شود و سایر سرویس‌ها آن احراز هویت را می‌پذیرند.

**استانداردهای رایج:** SAML، OAuth 2.0، OpenID Connect
**مثال:** ورود به Zoom با اکانت Google.

**مزایا:** بی‌نیازی به حساب‌های متعدد، سادگی احراز هویت بین‌سازمانی.

### Single Sign-On (SSO)

یک‌بار ورود برای دسترسی به چند سرویس مرتبط.
**مثال:** پس از ورود به Microsoft 365، دسترسی به Outlook، Teams و OneDrive بدون ورود مجدد.

**مزایا:**
- بهبود تجربهٔ کاربر
- کاهش حملات مرتبط با رمز عبور
- مدیریت آسان‌تر حساب‌ها

**معایب:**
- در صورت نفوذ به حساب مرکزی، تمام سرویس‌ها در خطر هستند.
- نیازمند امنیت قوی بک‌اند (MFA، مانیتورینگ و ...)

---

## ۸. AAA – Authentication، Authorization و Accounting

AAA چارچوبی امنیتی است که سه سرویس ارائه می‌دهد:

- **Authentication** — تأیید اینکه شما کی هستید (از طریق نام‌کاربری/رمز عبور، توکن، گواهینامهٔ دیجیتال و ...)
- **Authorization** — تعیین اینکه مجاز به انجام چه کاری هستید (دسترسی به شبکه، دستورات خاص، سرویس‌ها)
- **Accounting** — ثبت اینکه چه کردید، چه زمانی، و برای چه مدت

**پروتکل‌های رایج AAA:**
- **RADIUS**
- **TACACS+**

**موارد کاربرد:**
- ورود راه‌دور به روترها و سوییچ‌ها
- کنترل دسترسی VPN
- کنترل دسترسی مبتنی بر نقش و ثبت جزئیات فعالیت

## ۹. دموی عملی: ابزار CUPP (Common User Passwords Profiler)

CUPP یک ابزار متن‌باز پایتون است که برای تولید دیکشنری رمز عبور هدفمند بر اساس اطلاعات شخصی یک قربانی (در محیط آزمایشی یا تست نفوذ) استفاده می‌شود. این ابزار نشان می‌دهد رمزهای عبوری که بر اساس اطلاعات شخصی ساخته می‌شوند (نام، تاریخ تولد و ...) چقدر آسیب‌پذیرند.

### نصب

```bash
git clone https://github.com/Mebus/cupp
cd cupp-master
python3 cupp.py -h
```

### نحوهٔ اجرای حالت Interactive

```bash
python3 cupp.py -i
```

گزینه‌های اصلی:

| گزینه | توضیح |
|---|---|
| `-i` / `--interactive` | پرسش تعاملی برای پروفایل‌سازی رمز عبور |
| `-w FILENAME` | بهبود دیکشنری موجود با خروجی pwnsauce |
| `-l` | دانلود لیست‌های کلمات حجیم از مخزن |
| `-a` | تجزیهٔ نام‌کاربری‌ها و رمزهای پیش‌فرض از پایگاه داده Alecto |
| `--version` | نمایش نسخهٔ برنامه |

## ۱۰. Security Filtering (فیلترینگ امنیتی)

### Access Control Lists (ACLs)

قوانینی که روی اینترفیس‌های روتر یا سوییچ اعمال می‌شوند و تعیین می‌کنند بسته‌ها بر اساس موارد زیر مجاز یا رد شوند:
- آدرس IP مبدأ
- آدرس IP مقصد
- پروتکل یا شمارهٔ پورت

**انواع:**
- **Standard ACL:** فقط بر اساس IP مبدأ فیلتر می‌کند.
- **Extended ACL:** بر اساس مبدأ، مقصد، پروتکل و پورت فیلتر می‌کند.

### Tunneling

فرآیند캡سوله‌سازی ترافیک در یک پوشش امن برای انتقال از طریق شبکه‌های ناامن. در VPNها استفاده می‌شود (GRE، IPsec، L2TP).

### Encryption (رمزنگاری)

رمزنگاری محرمانه‌بودن داده را در حین انتقال یا در حال استراحت تضمین می‌کند:
- **Symmetric:** مانند AES
- **Asymmetric:** مانند RSA

### Remote Access

امکان اتصال مدیران به شبکه از موقعیت‌های خارجی:
- پروتکل‌های رایج: SSH، VPN، RDP
- نیازمند احراز هویت امن و رمزنگاری.

## ۱۱. جلوگیری از نشت داده (Data Loss Prevention — DLP)

### تعریف

DLP به فناوری‌ها و سیاست‌هایی اشاره دارد که از خروج داده‌های حساس از سازمان جلوگیری می‌کنند. محافظت از:
- اطلاعات شناسایی شخصی (PII)
- سوابق مالی یا بهداشتی
- مالکیت فکری (مانند کد منبع، نقشه‌ها)

### انواع DLP

| نوع | توضیح |
|---|---|
| **Network DLP** | نظارت بر ترافیک خروجی شبکه |
| **Endpoint DLP** | کنترل فعالیت کاربر روی دستگاه‌ها |
| **Cloud DLP** | حفاظت از داده در پلتفرم‌های ابری (مانند Google Drive، O365) |

### اهمیت DLP

- جلوگیری از نشت داده تصادفی یا عمدی
- کمک به رعایت الزامات انطباق (مانند GDPR، HIPAA)
- کاهش ریسک نقض داده و آسیب به شهرت

---

## ۱۲. مدیریت دستگاه‌های موبایل (Mobile Device Management — MDM)

### تعریف

MDM به مجموعه‌ای از ابزارها و سیاست‌ها اشاره دارد که برای مدیریت، کنترل و ایمن‌سازی دستگاه‌های موبایل (گوشی‌های هوشمند، تبلت‌ها و لپ‌تاپ‌های) متصل به شبکهٔ شرکتی استفاده می‌شود.

### وظایف کلیدی MDM

- پیکربندی دستگاه‌ها (Wi-Fi، VPN، ایمیل و ...)
- اجرای سیاست‌های امنیتی (قوانین رمز عبور، رمزنگاری داده)
- کنترل دسترسی به منابع شرکتی
- قفل از راه دور یا پاک‌سازی اطلاعات در صورت گم‌شدن یا سرقت
- نظارت بر برنامه‌ها و مدیریت به‌روزرسانی‌های نرم‌افزاری

### مزایای MDM برای سازمان‌ها

- ایمن‌سازی داده روی دستگاه‌های BYOD
- اجرای کنترل روی استفاده از منابع شرکتی
- پاسخ سریع به تهدیدات امنیتی مرتبط با دستگاه
- حفظ انطباق با سیاست‌های قانونی و داخلی

---

## ۱۳. Patch Management

### تعریف

Patch Management فرآیند نصب و مدیریت به‌روزرسانی‌های نرم‌افزاری (وصله‌ها) برای رفع اشکالات، پوشاندن آسیب‌پذیری‌های امنیتی و بهبود عملکرد است.

### اهمیت Patch Management

- **Enhances Security:** جلوگیری از بهره‌برداری از آسیب‌پذیری‌های شناخته‌شده
- **Improves System Stability:** کاهش خرابی‌ها و اختلالات عملکردی
- **Compliance:** کمک به رعایت استانداردهای قانونی و سازمانی
- **Centralized Control:** اطمینان از به‌روز بودن یکپارچهٔ تمام سیستم‌ها

### مراحل کلیدی فرآیند

1. شناسایی نرم‌افزارهای قدیمی
2. ارزیابی ریسک و ارتباط وصله‌ها
3. آزمایش وصله‌ها در محیط Sandbox/Test
4. استقرار وصله‌ها در زمان‌های کم‌استفاده (Low-Usage Windows)
5. نظارت بر نتایج و نگهداری لاگ‌ها

---

## ۱۴. آموزش آگاهی امنیتی (Security Awareness Training)

### تعریف

Security Awareness Training فرآیندی مستمر است که کارکنان را آموزش می‌دهد تا:
- تهدیدات امنیتی را شناسایی کنند
- بهترین شیوه‌ها را رعایت کنند
- به‌درستی به حملاتی مانند فیشینگ، مهندسی اجتماعی و بدافزار پاسخ دهند

### چرا حیاتی است؟

- کاربران ضعیف‌ترین حلقهٔ زنجیرهٔ امنیت هستند.
- ۹۰٪ نقض‌های امنیتی از خطای انسانی ناشی می‌شوند.
- جلوگیری از کلیک کاربران روی ایمیل‌ها یا لینک‌های مخرب
- بهبود انطباق با سیاست‌های امنیتی داخلی

### موضوعات کلیدی آموزشی

- شناسایی و پاسخ به فیشینگ
- عادات رمز عبور قوی
- برخورد با دستگاه‌های ناشناس (مانند USB)
- آگاهی از سیاست BYOD و دسترسی
- رویه‌های گزارش سریع حوادث

## ۱۵. امنیت دستگاه‌های موبایل (Mobile Device Security)

Mobile Device Security شامل سیاست‌ها، فناوری‌ها و رویه‌هایی است که گوشی‌های هوشمند، تبلت‌ها و لپ‌تاپ‌ها را در برابر **تهدیدات سایبری و فیزیکی** محافظت می‌کند.

**چرا اهمیت دارد؟**
- دستگاه‌ها اغلب به شبکه‌های عمومی ناامن وصل می‌شوند.
- فیشینگ، بدافزار و سرقت فیزیکی کاربران موبایل را هدف می‌گیرد.
- داده‌های حساس ممکن است از طریق دستگاه‌های موبایل ذخیره یا منتقل شوند.

**اقدامات امنیتی کلیدی:**
- فعال‌سازی **رمزنگاری کامل دستگاه (Full Device Encryption)**
- استفاده از **قفل صفحه قوی** (PIN، بیومتریک)
- استفاده از **Mobile Device Management (MDM)**
- اجتناب از اتصال به **Wi-Fi عمومی ناامن**
- **به‌روزرسانی منظم** سیستم‌عامل و برنامه‌ها

## ۱۶. سیاست‌ها و رویه‌های امنیتی (Security Policies and Procedures)

### تعریف

سیاست‌ها و رویه‌های امنیتی مجموعه‌ای از قوانین، استانداردها و رهنمودها هستند که برای مدیریت و حفاظت از دارایی‌های اطلاعاتی یک سازمان طراحی شده‌اند. اصولی را حفظ می‌کنند: **محرمانگی، صداقت و دسترس‌پذیری (CIA)**.

**اهمیت:**
- تعریف مسئولیت‌ها و رفتار قابل قبول کاربران
- به حداقل رساندن خطای انسانی و تهدیدات داخلی
- ارائهٔ چارچوبی برای پاسخ به حادثه و پاسخگویی
- پشتیبانی از الزامات انطباق و ممیزی

### سیاست‌ها و رویه‌های رایج

| نوع سیاست | توضیح |
|---|---|
| **Acceptable Use Policy** | کاربردهای مجاز و ممنوع منابع IT را مشخص می‌کند |
| **Password Policy** | الزامات پیچیدگی و تغییر دوره‌ای رمز عبور را اجرا می‌کند |
| **Incident Response Policy** | واکنش سازمان به حوادث امنیتی را راهنمایی می‌کند |
| **Remote Access Policy** | اتصال راه‌دور امن به سیستم‌های داخلی را مدیریت می‌کند |
| **Data Classification Policy** | سطوح حساسیت داده و نحوهٔ مدیریت مناسب را تعریف می‌کند |

## ۱۷. Hash در احراز هویت

**Hashing** یک فرآیند رمزنگاری یک‌طرفه است که رمزهای عبور را به مقادیر با اندازهٔ ثابت تبدیل و در پایگاه‌داده ذخیره می‌کند.

| الگوریتم | یادداشت |
|---|---|
| **MD5** | سریع اما در برابر تصادم (Collision) آسیب‌پذیر است |
| **SHA-1** | به‌دلیل ضعف‌های شناخته‌شده منسوخ شده است |
| **SHA-256** | امن، کاربرد گسترده |
| **bcrypt** | از Salt استفاده می‌کند؛ کند و در برابر Brute-Force مقاوم است |
| **scrypt / Argon2** | برای هشینگ امن رمز عبور طراحی شده‌اند |

> **نکتهٔ آزمون:** MD5 و SHA-1 دیگر برای هشینگ رمز عبور توصیه نمی‌شوند. SHA-256 برای صداقت (Integrity) داده مناسب است، اما bcrypt، scrypt یا Argon2 گزینه‌های بهتری برای ذخیرهٔ رمز عبور هستند زیرا عمداً کند طراحی شده‌اند (برای مقاومت در برابر حملات Brute-Force).

## جمع‌بندی نهایی

| مفهوم | نکتهٔ کلیدی |
|---|---|
| Authentication | «تو کی هستی؟» — رمز عبور، بیومتریک، کارت هوشمند |
| Authorization | «مجاز به چه کاری هستی؟» — نقش‌ها و مجوزها |
| MFA | سه عامل: something you know / have / are |
| RBAC / ABAC / DAC | سه مدل دسترسی: نقش‌محور، ویژگی‌محور، صاحب‌محور |
| SSO / Identity Federation | یک‌بار ورود؛ SAML / OAuth 2.0 / OpenID Connect |
| AAA | Authentication + Authorization + Accounting؛ RADIUS / TACACS+ |
| CUPP | ابزار تولید دیکشنری رمز عبور برای نشان دادن آسیب‌پذیری رمزهای شخصی |
| Security Filtering | ACL (Standard/Extended)، Tunneling، Encryption، Remote Access |
| DLP | Network / Endpoint / Cloud — جلوگیری از نشت داده |
| MDM | مدیریت دستگاه‌های موبایل شرکتی؛ Remote Wipe، Policy Enforcement |
| Patch Management | شناسایی → ارزیابی → آزمایش → استقرار → نظارت |
| Security Awareness | کاربران = ضعیف‌ترین حلقه؛ ۹۰٪ نقض‌ها از خطای انسانی |
| Hash | MD5/SHA-1 منسوخ؛ SHA-256 برای Integrity؛ bcrypt/Argon2 برای رمز عبور |
