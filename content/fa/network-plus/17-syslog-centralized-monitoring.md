# مانیتورینگ متمرکز با Syslog

## اهداف و چرایی اهمیت Syslog

**هدف کلیدی این بخش:**
- درک مفهوم و ساختار Syslog
- پیکربندی Syslog روی دستگاه‌های شبکهٔ سیسکو
- آشنایی با ابزارهای سرور Syslog
- تحلیل داده‌های لاگ برای شناسایی مشکلات یا حملات
- یادگیری بهترین شیوه‌ها در مدیریت لاگ

**نتایج موردانتظار:** در پایان این بخش، فراگیر باید بتواند لاگ‌گیری Syslog را روی روتر و سوییچ پیکربندی کند، ابزار مناسب سرور Syslog را انتخاب کند، پیام‌های لاگ را برای عیب‌یابی تفسیر کند، و رویدادهای پایهٔ شبکه را شناسایی و به آن‌ها پاسخ دهد.

**چرا Syslog اهمیت دارد؟**
- لاگ‌ها نخستین خط دفاعی برای شناسایی رویدادها و حملات شبکه هستند.
- برای ممیزی (Audit)، انطباق با استانداردها (Compliance) و شفافیت عملیاتی ضروری‌اند.
- Syslog روشی گسترده‌پشتیبانی‌شده و سبک برای لاگ‌گیری متمرکز است.

---

## Syslog چیست؟

**تعریف:** Syslog یک پروتکل استاندارد است که برای ارسال پیام‌های لاگ و رویداد از دستگاه‌های شبکه به یک سرور لاگ مرکزی استفاده می‌شود.

**نحوهٔ عملکرد:**
1. دستگاه‌ها پیام‌های لاگ تولید می‌کنند.
2. این لاگ‌ها با استفاده از **پورت UDP شمارهٔ ۵۱۴** به سمت سرور Syslog ارسال می‌شوند.
3. مدیران شبکه از این سرور برای بررسی و تحلیل متمرکز لاگ‌ها استفاده می‌کنند.

**چرا اهمیت دارد؟**
- شناسایی مشکلات دستگاه (مانند قطع لینک یا تغییر پیکربندی)
- پشتیبانی از مانیتورینگ رویدادهای امنیتی
- امکان ممیزی انطباق (Compliance Auditing)
- شناسایی زودهنگام رفتارهای مخرب

## سطوح Severity در Syslog

هر پیام Syslog با یک سطح Severity بین ۰ تا ۷ مشخص می‌شود که میزان بحرانی بودن رویداد را نشان می‌دهد؛ هرچه عدد کوچک‌تر باشد، رویداد بحرانی‌تر است.

| کد | نام سطح | توضیح | نمونه |
|---|---|---|---|
| 0 | Emergency | سیستم غیرقابل‌استفاده است. | خرابی کامل سیستم (Complete Crash) |
| 1 | Alert | نیاز به اقدام فوری. | خرابی دیسک |
| 2 | Critical | وضعیت بحرانی اما هنوز قابل جبران. | — |
| 3 | Error | یک خطای غیربحرانی رخ داده. | خرابی یک اینترفیس |
| 4 | Warning | مشکل بالقوه که ممکن است تشدید شود. | — |
| 5 | Notice | رویداد مهم، اما نه یک خطا. | — |
| 6 | Informational | پیام‌های عمومی عملیاتی. | راه‌اندازی سرویس، بوت شدن، ورود کاربر |
| 7 | Debug | پیام‌های سطح دیباگ، برای توسعه‌دهندگان. | مفید برای عیب‌یابی توسعه |

## ساختار پیام Syslog

یک پیام معمول Syslog این ساختار را دارد:

```
<PRI>timestamp hostname tag: message
```

| بخش | توضیح |
|---|---|
| `<PRI>` | اولویت رمزگذاری‌شده، طبق فرمول: **Facility × 8 + Severity** |
| `timestamp` | زمان وقوع رویداد |
| `hostname` | نام یا IP دستگاه مبدأ |
| `tag` | فرآیند یا ماژولی که لاگ را تولید کرده |
| `message` | توضیح رویداد |

**نمونهٔ واقعی:**

```
<189>Jan 14 10:24:01 router01 SSHD[12345]: Login successful from 192.168.1.100
```

**تجزیهٔ پیام:**
- `<189>` → Facility 23 (local7)، Severity 5 (Notice) — چون: 23 × 8 + 5 = 189
- `Jan 14 10:24:01` → زمان رویداد
- `router01` → نام میزبان
- `SSHD[12345]` → فرآیند (سرویس SSH با شناسهٔ فرآیند 12345)
- `Login successful...` → متن پیام

### کدهای Facility در Syslog

فیلد Facility مشخص می‌کند پیام از کدام دسته/زیرسیستم دستگاه تولید شده است:

| کد | توضیح |
|---|---|
| 0 | Kernel |
| 1 | User |
| 2 | Mail |
| 3 | System daemons |
| 4 | Security/authorization messages |
| 5 | Internal syslog daemon messages |
| 6 | Line printer subsystem |
| 7 | Network news subsystem |
| 8 | UUCP subsystem |
| 9 | Clock daemon |
| 10 | Security/auth messages |
| 11 | FTP daemon |
| 12 | NTP subsystem |
| 13 | Log audit |
| 14 | Log alert |
| 15 | Clock schedule daemon |
| 16–23 | Facilityهای اختصاصی محلی (local0 تا local7) |

> **نکتهٔ آزمون:** مقدار `<PRI>` هرگز به‌صورت مستقیم Facility و Severity را نشان نمی‌دهد؛ باید آن را طبق فرمول `Facility × 8 + Severity` تجزیه کرد. برای مثال، `<189>` در نگاه اول فقط یک عدد است، اما پس از تجزیه، Facility=23 (یعنی local7) و Severity=5 (Notice) را نشان می‌دهد.

## پیکربندی Syslog روی روتر/سوییچ سیسکو

```
Router> enable
Router# configure terminal
Router(config)# logging 192.168.1.100
Router(config)# logging trap warnings
Router(config)# service timestamps log datetime msec
Router(config)# logging console [Optional]
Router(config)# end
```

**توضیح دستورات:**
- `logging 192.168.1.100` → مشخص کردن آدرس IP سرور Syslog مقصد
- `logging trap warnings` → ارسال فقط پیام‌هایی با سطح Warning (کد ۴) و بحرانی‌تر از آن به سرور
- `service timestamps log datetime msec` → افزودن مهر زمانی دقیق (با دقت میلی‌ثانیه) به هر پیام لاگ
- `logging console` → نمایش پیام‌های لاگ روی خط کنسول (اختیاری، معمولاً در محیط Production به‌دلیل حجم بالا غیرفعال می‌شود)

## ابزارهای دریافت‌کنندهٔ Syslog (Syslog Receiver Tools)

| ابزار | پلتفرم | ویژگی‌ها | نقاط قوت |
|---|---|---|---|
| **Kiwi Syslog** | Windows | دریافت‌کنندهٔ لاگ مبتنی بر رابط گرافیکی، با قابلیت فیلترینگ و هشدار | نصب آسان / رایگان |
| **Graylog** | Linux / Windows | تجمیع لاگ، داشبورد و تحلیل | مقیاس‌پذیر و مناسب محیط سازمانی |
| **Syslog-ng** | Linux | جمع‌آوری‌کنندهٔ لاگ با کارایی بالا و خروجی قابل‌تنظیم | مسیریابی/فیلترینگ پیشرفته |
| **TFTPD32** | Windows | ابزار سبک با پشتیبانی هم‌زمان از Syslog، DHCP و TFTP | ساده و چندمنظوره |

## فیلترینگ و تحلیل لاگ‌های Syslog با ابزارها

### Kiwi Syslog Server

**نوع:** ابزار رایگان مشاهدهٔ Syslog با رابط گرافیکی ویندوز.

**ویژگی‌ها:**
- فیلتر کردن لاگ‌ها بر اساس Severity
- برجسته‌سازی الگوهای خاص (مانند قطع شدن یک پورت)
- ارسال هشدار از طریق صدا یا ایمیل

**سناریوی نمونه:**
1. یک سوییچ سیسکو یک لاگ خطا (Severity 3) ارسال می‌کند.
2. Kiwi تنظیم شده تا فقط سطوح ۰ تا ۳ را فیلتر و نمایش دهد؛ این پیام نمایش داده می‌شود.
3. مدیر شبکه بررسی می‌کند که کدام اینترفیس باعث این مشکل شده است.

### Graylog

**نوع:** جمع‌آورندهٔ لاگ متن‌باز و در سطح سازمانی.

**ویژگی‌ها:**
- جست‌وجو و فیلترینگ پیشرفته
- داشبوردهای بلادرنگ (Real-time)
- هشداردهی هنگام شناسایی الگوهای مشخص

**نمونهٔ کوئری جست‌وجو در Graylog:**

```
facility:local7 AND severity:3 AND source:switch-1
```

این کوئری تمام پیام‌هایی را نمایش می‌دهد که از Facility با نام `local7`، با سطح Severity برابر ۳ (Error)، و از منبع `switch-1` ارسال شده باشند — نمونه‌ای دقیق از نحوهٔ ترکیب فیلدهای پیام Syslog برای یافتن سریع رویداد موردنظر در حجم بالای لاگ.

## جمع‌بندی نهایی

| مفهوم | نکتهٔ کلیدی |
|---|---|
| Syslog | پروتکل استاندارد ارسال لاگ به سرور مرکزی، روی پورت UDP 514 |
| Severity | ۸ سطح (۰ تا ۷)؛ عدد کوچک‌تر یعنی بحرانی‌تر (0=Emergency، 7=Debug) |
| ساختار پیام | `<PRI>timestamp hostname tag: message` |
| PRI | Facility × 8 + Severity |
| Facility | دسته‌بندی منبع پیام (۰ تا ۲۳، شامل local0–local7) |
| پیکربندی سیسکو | `logging <IP>`، `logging trap <level>`، `service timestamps` |
| ابزارهای دریافت | Kiwi Syslog، Graylog، Syslog-ng، TFTPD32 |
| تحلیل لاگ | فیلتر بر اساس Severity/Facility/Source برای یافتن سریع رویداد |
